### 3. 前后端关系

前端 Vite 与 FastAPI 独立运行。开发时前端请求 `/api/...`，Vite 将请求转发到 `http://127.0.0.1:8080/api/...`。当前保留 `/api` 前缀，没有 rewrite；后端路由尚未确定，后续应确认是否实际挂载 `/api` 前缀。

代理配置只服务开发服务器，不会启动 FastAPI，不代表生产部署的反向代理。生产环境需单独设置网关/反向代理或后端跨域策略。业务代码尚未接入 Axios 或真实接口。

### 4. 配置之间的关系

1. Vite 使用 Vue 插件处理组件并解析运行时别名；应用 TS 配置提供相同别名给类型检查与编辑器。
2. 根 TS 配置通过 references 分离浏览器应用代码和 Node 配置代码；`vue-tsc -b` 遍历两个子项目。
3. Vitest 合并 Vite 配置，组件测试沿用相同编译与路径解析方式。
4. ESLint 检查代码质量，Prettier 负责格式；末尾的兼容配置只关闭冲突规则，不会在 ESLint 中运行 Prettier。
5. `.gitignore` 排除 Vite、Vitest 和 TypeScript 等工具生成的文件。

### 5. 测试目录约定与执行边界

测试用例命名为 `*.test.ts`、`*.spec.ts`，也支持相同命名的 JavaScript 文件。匹配位置为 `frontend/tests/` 与 `frontend/src/` 下，例如 `src/components/__tests__/Example.spec.ts`。仓库根目录的 `tests/` 不在本次前端测试扫描范围内，避免混入后端测试。TypeScript 子项目重点检查 TS 测试文件，JS 用例由 ESLint 检查。

不设置 `passWithNoTests`，因此尚无测试文件时，未来执行 `test:run` 会按 Vitest 默认行为返回非零状态。本次没有执行测试、接口访问或任何真实业务操作。jsdom 和 mock 清理配置不提供网络隔离；未来编写用例时须 mock Axios、fetch 和写入类业务依赖，不连接真实业务后端。
