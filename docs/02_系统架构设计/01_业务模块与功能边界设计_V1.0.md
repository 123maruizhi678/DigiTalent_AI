## 一、设计目标与范围

本文件用于明确 AI
数字化人才平台七大业务模块的职责、内部功能组成、核心数据归属、模块间协作关系、公共业务能力边界及模块验收原则。

本步骤承接《01_系统总体架构设计.md》确定的前后端分离、模块化分层单体架构。本文聚焦业务模块与功能边界，不提前展开数据库表结构、API
详细字段、具体算法和代码实现。

当前业务范围包括：

1.  人才选拔。
2.  人才档案与人才画像。
3.  智能测评与面试。
4.  AI Agent 与工作流管理。
5.  数字员工与任务调度。
6.  数据智能与运营决策。
7.  用户、组织与权限管理。

明确不纳入当前业务范围：岗前培养与培训课程、企业知识库。

### 2.1 人才选拔模块按业务流程划分

人才选拔模块内部围绕招聘和选拔过程组织功能，包括招聘需求、岗位、候选人、简历、解析、筛选、匹配、邀请和流程管理。简历解析等通用技术能力可以由文档处理能力层提供，但简历在招聘场景中的业务管理责任属于人才选拔模块。

### 2.2 人才档案按数据类型与管理流程划分

人才档案模块按基础信息、教育经历、工作经历、项目经历、技能能力、标签、画像和档案版本等内容组织。人才画像不是独立于人才主档的数据孤岛，应关联其数据来源、生成时间和版本。

### 2.3 测评与面试按业务流程划分

测评方案、题库、任务、在线测评、评分、AI
面试、面试记录和报告形成完整业务链路。测评模块对完整过程数据和报告负责；其他模块通过授权服务读取所需结果或摘要。

### 2.4 Agent、Workflow、数字员工独立管理

三者不是同一个业务对象： - Agent 表示提供智能能力的执行单元。 - Workflow
表示组织节点、条件和状态流转的流程定义与执行实例。 -
数字员工表示业务层面的数字化执行主体，可以关联 Agent、Tools 和
Workflow。 - 任务调度负责具体任务的分配、触发、执行状态和结果记录。

它们通过明确的关联关系协作，不采用"一名数字员工必然等于一个
Agent"或"一个数字员工必然对应一个 Workflow"的简单绑定规则。

### 2.5 公共能力与业务规则分离

公共服务只提供通用能力，不接管业务模块的专属业务规则。例如： -
文件管理提供文件上传、存储、访问和元数据能力；简历归档规则仍属于人才选拔。 -
通知管理提供通知模板和发送能力；候选人邀请的业务条件和状态规则仍属于人才选拔。 -
任务记录提供通用任务记录能力；数字员工任务的业务编排仍属于数字员工与任务调度模块。

### 2.6 模块验收原则

每个模块必须明确： - 功能清单和子功能。 - 核心数据及权威归属。 -
输入、输出和状态变化。 - 对外提供的业务服务。 -
允许依赖的模块和公共能力。 - 明确不负责的功能。 - 可验证的模块验收标准。

**第五批评估结论：**
该批选择使各模块从"功能名称集合"进一步细化为可设计、可实现、可测试的业务边界。本步骤无需增加第六批，30
项确认已覆盖模块划分、功能范围、数据归属、模块协作、公共能力和验收原则。

## 四、七大业务模块总体定义

  --------------------------------------------------------------------------------------------------
  编号                    模块名称                模块定位
  ----------------------- ----------------------- --------------------------------------------------
  M01                     人才选拔                负责招聘需求、岗位、候选人及人才选拔全过程

  M02                     人才档案与人才画像      负责人才长期主档、经历、技能、标签和画像

  M03                     智能测评与面试          负责测评方案、题目、任务、面试、评分和报告

FastAPI 模块化分层单体应用中。

## 五、各业务模块详细功能与边界

## 5.1 M01 人才选拔

### 模块目标

围绕招聘需求和岗位，完成候选人收集、简历处理、AI
筛选、岗位匹配、候选人邀请及选拔过程跟踪。

### 功能清单

  子功能         功能说明
  -------------- --------------------------------------
  招聘需求管理   创建、维护和跟踪招聘需求
  岗位管理       维护岗位信息、职责、要求和能力条件
  候选人管理     管理进入选拔流程的候选人及其状态
  简历管理       管理候选人简历、附件和版本
  简历解析       调用文档处理能力，获取结构化简历内容
  AI 简历筛选    根据岗位要求辅助分析候选人匹配情况
  岗位人才匹配   计算或分析岗位与候选人的适配程度
  候选人邀请     发起候选人邀请，调用公共通知能力
  选拔流程管理   管理候选人各阶段状态、处理记录和结果

### 数据归属

人才选拔模块负责招聘需求、岗位、候选人选拔记录、简历业务关联、筛选结果和选拔过程数据。

### 输入与输出

-   输入：招聘需求、岗位条件、候选人资料、简历文件、测评结论等。
-   输出：候选人筛选结果、岗位匹配结果、邀请记录、选拔状态和选拔结论。

### 依赖关系

-   调用公共文件管理能力管理简历文件。
-   调用文档处理能力解析简历。
-   调用 Agent 管理中心提供的筛选和匹配智能能力。
-   发起测评需求，由测评模块独立执行。
-   调用通知公共能力发送候选人邀请。
-   通过人才档案服务创建或关联正式人才档案。

### 不负责的事项

-   不负责人才长期主档的权威维护。
-   不保存测评模块的完整答题和面试过程数据。
-   不直接管理 Agent 或 Workflow 定义。
-   不自行实现底层文件存储和通知发送基础能力。

## 5.2 M02 人才档案与人才画像

### 模块目标

建立人才长期信息的权威管理体系，形成结构化人才档案和可追溯的人才画像。

### 功能清单

  子功能               功能说明
  -------------------- --------------------------------------------
  人才基础档案         管理人才基本信息及主档标识
  教育经历             管理学历、学校、专业和时间等经历
  工作经历             管理任职经历、岗位和工作内容
  项目经历             管理项目参与情况和项目成果
  技能与能力           管理技能、能力项及相关证据
  人才标签             管理人才分类标签及其来源
  人才画像             综合结构化信息、规则计算和 AI 分析形成画像
  档案版本与变更记录   记录档案变更、画像版本和数据来源
  测评结果关联         关联测评结论、能力摘要和报告引用

### 数据归属

人才档案模块是人才长期信息的权威管理方。候选人通过选拔后，按业务规则创建或关联人才档案。

### 输入与输出

-   输入：候选人转入信息、人才基础资料、经历、技能、测评结果摘要、人工修订信息。
-   输出：人才主档、人才画像、人才标签、能力摘要、档案版本和变更记录。

### 依赖关系

-   通过人才选拔服务接收候选人转入或关联请求。
-   通过测评服务读取授权的测评结论。
-   调用 Agent 能力辅助经历分析、能力提取和画像总结。
-   调用数据服务提供授权的统计分析数据。

### 不负责的事项

-   不管理招聘需求和候选人选拔流程。
-   不管理完整测评任务、答题记录和面试过程。
-   不把 AI 生成结果未经审核直接视为事实。
-   不承担跨业务数据分析平台的全部职责。

## 5.3 M03 智能测评与面试

### 模块目标

提供完整的测评和面试业务能力，形成可追踪、可审核的测评过程和结果。

### 功能清单

  子功能         功能说明
  -------------- --------------------------------
  测评方案管理   定义测评类型、规则和适用场景
  题库管理       管理题目、选项、题型和评分规则
  测评任务管理   创建、分配和跟踪测评任务
  在线测评       支持候选人完成测评
  自动评分       根据规则或 AI 能力辅助评分
  AI 面试        提供 AI 面试交互和过程管理
  面试记录       保存面试过程、问题、回答和评价
  测评报告       生成和管理完整测评报告
  面试报告       生成和管理面试评价报告

### 数据归属

测评模块负责测评方案、题库、测评任务、答题记录、评分、面试过程和完整报告。

人才档案只关联所需结果摘要或报告引用，不复制整套测评过程数据。

### 输入与输出

-   输入：人才或候选人标识、测评需求、测评方案、题目、面试配置。
-   输出：测评状态、评分、面试评价、完整报告和可供其他模块使用的结果摘要。

### 依赖关系

-   接收人才选拔模块发起的测评需求。
-   调用 Agent 管理中心提供的测评分析、问题生成或面试智能能力。
-   调用公共文件管理能力保存相关附件和报告。
-   调用通知能力发送测评通知。
-   向人才档案和人才选拔提供授权结果。

### 不负责的事项

-   不管理招聘需求和岗位。
-   不负责人才长期主档。
-   不自行维护统一 Agent 注册体系。
-   不承担全平台任务调度管理。

## 5.4 M04 AI Agent 与工作流管理

### 模块目标

统一管理平台使用的 Agent 和 Workflow，使智能能力可配置、可复用、可追踪。

### 功能清单

  子功能                   功能说明
  ------------------------ -------------------------------------
  Agent 注册与管理         注册、查询和管理 Agent
  Agent 配置               管理模型、工具和运行参数等配置
  Agent 版本管理           管理 Agent 版本和变更
  Prompt 管理              管理提示词模板及版本
  Tools 管理               管理可供 Agent 使用的工具定义
  Workflow 定义            管理工作流结构、节点和条件
  Workflow 版本管理        管理工作流版本和变更
  Workflow 执行记录        查询工作流执行状态和结果
  Agent 运行状态           管理和展示 Agent 可用状态及运行信息
  Agent 与 Workflow 关联   管理智能能力与工作流之间的关系

### 数据归属

负责 Agent 定义、配置、版本、Prompt、Tools 元数据、Workflow
定义及执行管理数据。

### 输入与输出

-   输入：Agent 定义、模型配置、Prompt、Tools、Workflow
    定义和业务调用请求。
-   输出：可调用的 Agent 能力、Workflow 执行结果、运行状态和执行记录。

### 依赖关系

-   通过统一模型适配接口调用模型服务。
-   通过基础设施适配层访问外部工具或服务。
-   供人才选拔、人才档案、测评和数字员工模块按需调用。
-   与数字员工模块建立 Agent、Workflow 关联关系。

### 不负责的事项

-   不直接拥有候选人、人才档案或测评等核心业务数据。
-   不代替业务模块执行最终业务状态变更。
-   不负责数字员工的业务身份管理。
-   不负责平台所有业务任务的调度和分配。

## 5.5 M05 数字员工与任务调度

### 模块目标

管理数字员工这一业务执行主体，组合智能能力，并对任务分配、调度和执行情况进行管理。

### 功能清单

  子功能           功能说明
  ---------------- --------------------------------------
  数字员工创建     创建数字员工业务对象
  数字员工配置     管理名称、用途、状态和运行配置
  Agent 关联       关联可用 Agent
  Workflow 关联    关联可用工作流
  能力配置         组合数字员工可使用的能力和工具
  任务创建与分配   创建任务并分配给适当执行主体
  任务执行调度     管理任务触发、排队或执行安排
  执行状态管理     管理待执行、执行中、成功、失败等状态
  执行结果记录     记录结果引用、执行摘要和异常
  失败与重试管理   按策略处理失败任务和重试
  运行监控         查看数字员工和任务执行情况

### 数据归属

负责数字员工定义、能力关联、任务分配、调度信息和执行记录。通用任务记录能力可以由公共服务提供，但数字员工任务的业务规则归属本模块。

### 输入与输出

-   输入：数字员工配置、Agent/Workflow 关联、任务请求、调度条件。
-   输出：任务执行状态、执行结果、失败记录、运行统计和监控信息。

### 依赖关系

-   调用 Agent 与工作流管理模块提供的能力。
-   使用公共任务记录、通知和业务事件能力。
-   按任务类型调用相应业务模块或服务。
-   使用统一基础设施适配层访问外部服务。

### 不负责的事项

-   不负责 Agent 定义和 Prompt 版本的权威管理。
-   不替代 Workflow 的流程定义管理。
-   不直接修改其他业务模块的核心数据。
-   不把数字员工等同于 Agent。

## 5.6 M06 数据智能与运营决策

### 模块目标

在授权和符合数据权限要求的前提下，对平台业务数据进行统计、分析、可视化和决策辅助。

### 功能清单

  子功能             功能说明
  ------------------ --------------------------------
  人才数据统计       统计人才规模、结构和分布
  招聘数据分析       分析招聘需求、候选人和选拔过程
  人才结构分析       分析人才属性和能力结构
  人才质量分析       基于明确指标分析人才质量
  测评数据分析       分析测评结果和能力分布
  Agent 运行分析     分析 Agent 调用和运行情况
  数字员工运行分析   分析数字员工任务执行情况
  运营指标管理       定义和维护运营指标口径
  可视化报表         提供统计图表和报表
  决策辅助分析       基于授权数据形成分析结论和建议

### 数据归属

本模块负责分析模型、指标口径、统计结果、报表和分析记录；不成为人才、招聘或测评等业务主数据的权威管理方。

### 输入与输出

-   输入：各业务模块授权提供的数据、指标定义和分析条件。
-   输出：统计指标、分析结果、可视化报表和决策辅助建议。

### 依赖关系

-   通过授权的数据服务获取各业务模块数据。
-   遵循用户、组织和数据权限模块提供的权限约束。
-   可调用 AI 能力辅助分析，但分析结果需保留数据来源和口径。

### 不负责的事项

-   不直接修改人才档案、候选人和测评等业务主数据。
-   不绕过授权服务直接读取所有业务表。
-   不把 AI 推断结果当作未经验证的业务事实。

## 5.7 M07 用户、组织与权限管理

### 模块目标

提供平台统一身份、组织、角色、认证、授权和审计管理能力。

### 功能清单

  子功能           功能说明
  ---------------- ----------------------------------
  用户账号管理     创建、维护、停用和查询用户

  组织架构管理     管理组织及其层级关系
  部门管理         管理部门和部门归属
  角色管理         定义角色及其权限集合
  菜单权限         控制用户可访问的菜单
  功能权限         控制用户可执行的功能操作
  数据权限         控制用户可访问的数据范围
  操作审计         记录重要操作和安全相关事件
  登录与认证管理   处理登录、认证状态和会话相关管理

### 数据归属

负责用户、组织、部门、角色、权限策略和认证管理数据，以及平台统一审计管理职责。

### 输入与输出

### 不负责的事项

-   不因用户拥有菜单权限就默认拥有全部业务数据访问权限。

## 六、公共业务能力及边界

公共业务能力为多个业务模块提供通用服务。公共能力不应接管具体业务模块的专属业务规则。

  ---------------------------------------------------------------------------------------------------
  公共能力                负责内容                                 不负责内容
  ----------------------- ---------------------------------------- ----------------------------------
  文件管理                上传、下载、存储引用、元数据、访问控制   简历筛选规则、测评业务规则

  通知管理                通知模板、发送、发送记录和状态           候选人邀请资格和邀请流程规则

  任务记录                通用任务标识、状态和执行记录能力         数字员工的业务编排规则

  操作审计                通用操作审计记录                         各模块业务审批规则

  数据导入导出            通用文件导入导出能力                     各业务对象的数据校验规则

  通用状态能力            可复用的基础状态处理约定                 代替业务模块定义全部业务状态

  业务事件                事件定义、发布或分发基础能力、处理记录   代替业务模块决定何时发生业务事件
  ---------------------------------------------------------------------------------------------------

### 6.1 文件管理边界

公共文件管理负责文件生命周期和访问能力。业务模块决定文件的业务类型、关联对象、可见范围和业务校验要求。文档处理层负责文件内容解析，不等同于文件管理。

### 6.2 通知管理边界

通知公共能力负责发送渠道适配、模板、发送记录和失败状态。业务模块负责触发条件、接收对象、业务内容和后续状态变更。

### 6.3 任务记录边界

公共任务记录可为多个模块提供统一记录结构。数字员工与任务调度模块仍负责数字员工任务的分配、调度策略和业务执行规则。

### 6.4 业务事件边界

业务模块决定何时产生事件以及事件表达的业务事实；公共事件能力负责通用的事件传递和处理记录。具体是否采用进程内事件、持久化事件表或其他机制，在后续服务交互与运行机制设计中确定。本步骤不据此引入消息队列。

## 九、模块依赖与调用约束

1.  每个核心业务数据对象必须有明确的权威管理模块。
2.  模块之间通过对外业务服务接口共享数据，不直接修改对方内部数据。
3.  不允许形成循环依赖；若两个模块存在双向业务协作，应通过明确的接口、事件或应用层编排处理。
4.  Agent 提供智能能力，不直接绕过业务模块修改核心业务数据。
5.  Workflow 负责流程编排，不替代业务模块的业务规则。
6.  公共服务提供通用能力，不接管业务专属规则。
7.  数据智能通过授权数据服务获取数据，不直接拥有业务主数据。
8.  用户权限模块提供统一认证授权能力，业务模块仍需进行具体资源和数据范围检查。
9.  跨模块操作应明确发起方、被调用方、输入、输出、失败处理和审计要求。
10. 模块间调用方式遵循总体架构：同一 FastAPI
    应用内优先进程内服务调用，独立技术服务通过适配层调用。
