## 一、阶段目标

本阶段以已经确认的项目需求、业务对象、功能范围和业务流程为依据，对 2026
AI 数字化人才平台进行系统性技术可行性评估。

重点判断：

1.  当前业务需求是否能够通过合理的技术架构实现。
2.  各业务模块、AI 中台和基础设施之间的职责边界是否清晰。
3.  技术组件是否适合平台的业务规模、功能复杂度和部署要求。
4.  人才业务、智能测评、Agent、数字员工和数据智能能力是否具备可落地的实现路径。
5.  数据、安全、权限、性能、稳定性方面是否存在明显风险。
6.  是否需要调整现有技术方案，以及进入后续设计和开发前还需要解决哪些问题。

本阶段以技术分析、方案比较、可行性判断和决策记录为主，不提前开展完整业务功能开发。

## 二、评估范围

当前纳入评估的七大业务领域：

1.  人才选拔。
2.  人才档案与人才画像。
3.  智能测评与面试。
4.  AI Agent 与工作流管理。
5.  数字员工与任务调度。
6.  数据智能与运营决策。
7.  用户、组织与权限管理。

岗前培养与培训课程、企业知识库不纳入当前版本范围。

评估时应遵循已确认的业务关系：

-   项目群包含多个项目，项目包含一个或多个项目需求。
-   同一自然人使用统一人才主档案，候选人和员工分别保留对应业务身份及阶段记录。
-   人才画像采用 AI 生成草稿、HR 确认后保存正式画像的机制。
-   数字员工承担业务职责，Agent 提供专业任务能力；数字员工可以关联多个
    Agent 和 Workflow。
-   Workflow 负责组织任务或多个 Agent 的执行过程。
-   错题记录与管理保留，独立错题复习计划不纳入当前范围。

## 四、各步骤详细内容

### 第 1 步：总体技术架构可行性评估

**目标：** 判断平台整体架构是否能够支撑七大业务领域，并明确业务系统、AI
中台、任务调度和基础设施之间的关系。

评估内容：

1.  前后端分离架构是否适用。
2.  平台整体分层是否合理，包括表现层、接入层、业务应用层、AI
    中台层、任务调度层、数据访问层和基础设施层。
3.  七大业务领域的模块边界、职责和依赖关系是否清晰。
4.  业务应用层与 AI 中台之间如何分工。
5.  Agent、Workflow、数字员工和任务调度之间的关系是否合理。
6.  核心业务数据、AI 配置数据、AI
    运行数据、文件数据和审计数据如何分类与流转。
7.  同步请求、异步任务、定时任务和人工介入任务如何划分。
8.  用户权限、业务数据权限和 AI 工具权限应位于哪些架构层。
9.  是否存在模块耦合、职责重叠、单点依赖或过度设计风险。
10. 判断采用模块化单体、分层单体或服务拆分的合理性，不预设必须采用微服务。

预期交付物：

-   总体逻辑架构图。
-   系统模块职责表。
-   核心模块依赖关系图。
-   核心业务数据流转图。
-   关键业务协作流程图。
-   总体架构风险清单。
-   总体架构评估结论。

### 第 2 步：基础技术组件可行性评估

**目标：** 根据第 1
步确认的架构职责，判断平台所需基础技术组件是否适用，形成可落地的技术选型。

评估内容：

1.  前端框架及管理端、业务端的实现方式。
2.  后端语言、Web 框架及 API 组织方式。
3.  关系型数据库及数据访问方案。
4.  缓存技术及适用场景。
5.  文件存储及文件访问方案。
6.  消息队列和异步任务执行方案。
7.  定时、周期及手动任务调度方案。
8.  模型供应商接入及模型服务适配方案。
9.  部署方式、开发环境和运行环境要求。
10. 各组件之间的兼容性、维护成本和资源占用。

每项组件应记录：

-   解决的问题及使用位置。
-   推荐方案和备选方案。
-   优势、限制和适用条件。
-   与其他组件的依赖关系。
-   部署与维护成本。
-   是否保留现有选型或需要调整。

预期交付物：

-   基础技术组件清单。
-   技术选型对比表。
-   组件依赖关系说明。
-   最终选型建议及待确认事项。

### 第 3 步：人才业务核心技术评估

**目标：** 判断人才选拔、人才档案和人才画像相关功能的技术实现可行性。

评估内容：

1.  简历文件上传、批量接收和文件管理。
2.  PDF、DOCX 等简历格式的解析能力。
3.  简历信息抽取及结构化数据生成。
4.  简历解析失败、低质量内容和人工修正机制。
5.  候选人、员工与统一人才主档案之间的数据关联。
6.  岗位条件配置和岗位字典管理。
7.  硬性条件过滤与综合评分相结合的人才匹配方案。
8.  匹配分数、匹配原因和不满足条件的解释机制。
9.  AI 人才画像生成、草稿审核和正式画像更新机制。
10. 人才标签、能力维度、优势和待提升项的管理方式。
11. 简历、人才档案和画像数据更新后的关联处理。
12. 个人信息保护、数据访问和 AI 结果人工确认机制。

预期交付物：

-   简历解析技术方案。
-   人才匹配技术方案。
-   人才主档案数据关系说明。
-   人才画像生成与审核方案。
-   人才业务技术风险清单。

### 第 4 步：智能测评与面试技术评估

**目标：**
判断题库、组卷、在线测评、智能评分及面试管理的实现方式是否可行。

评估内容：

1.  题库、试题、分类和难度管理。
2.  试卷创建、题目抽取和智能组卷。
3.  在线测评的身份校验、答题过程和提交机制。
4.  客观题自动评分。
5.  主观题 AI 评分及评分依据。
6.  评分标准、评分结果和人工复核机制。
7.  测评结果、答卷和错题记录管理。
8.  面试邀约及多轮面试记录管理。
9.  测评与面试流程之间的衔接方式。
10. 防止重复提交、异常中断和评分结果丢失的机制。

预期交付物：

-   智能组卷技术方案。
-   在线测评技术方案。
-   客观题与主观题评分方案。
-   面试管理技术方案。
-   测评与面试技术风险清单。

### 第 5 步：AI Agent 与 Workflow 技术评估

**目标：** 判断 AI 中台能否统一管理
Agent、Workflow、模型供应商及工具调用，并支撑不同人才业务场景。

评估内容：

1.  Agent 注册、配置、启停、发布和版本管理。
2.  Agent 能力描述、输入输出和调用约定。
3.  Agent 工具注册、参数校验和权限控制。
4.  Workflow 定义、节点组织和执行分支。
5.  LangChain 等 Agent 框架的适用性。
6.  LangGraph 等工作流框架的适用性。
7.  多 Agent 协作、结果传递和上下文管理。
8.  Workflow 状态持久化、Checkpoint、中断和恢复。
9.  模型供应商统一接入、切换和配置管理。
10. Agent 执行记录、耗时、Token、错误和调用链追踪。
11. 人工确认、异常处理和失败重试机制。
12. AI 中台与业务服务之间的调用及结果回写边界。

预期交付物：

-   Agent 管理技术方案。
-   Workflow 编排技术方案。
-   多 Agent 协作方案。
-   模型供应商接入方案。
-   AI 中台模块职责与依赖关系。
-   Agent 安全及运行风险清单。

### 第 6 步：数字员工与任务调度技术评估

**目标：** 判断数字员工能否通过职责配置、Workflow 和 Agent
组合形成可管理、可调度、可追踪的数字化执行主体。

评估内容：

1.  数字员工注册、启用、停用和管理。
2.  数字员工职责描述与职责边界。
3.  数字员工与多个 Agent、Workflow 的关联关系。
4.  职责流程的定义和执行方式。
5.  定时、周期、手动及业务事件触发方式。
6.  任务分配、认领、排队和执行状态管理。
7.  异步任务、并发控制和资源限制。
8.  任务失败、超时、重试和人工介入机制。
9.  数字员工执行记录和结果追踪。
10. 成员即时通信账号关联的技术可行性及边界。
11. 数字员工的身份、权限和操作审计。

数字员工的具体业务职责及执行边界尚未明确的内容，应继续标记为待确认，不自行扩展业务范围。

预期交付物：

-   数字员工管理技术方案。
-   数字员工与 Agent、Workflow 关系图。
-   职责流程及任务执行方案。
-   调度机制与失败处理方案。
-   数字员工权限和审计方案。

### 第 7 步：数据智能与运营决策技术评估

**目标：**
判断平台能否在权限受控的前提下，通过自然语言查询业务数据并形成统计分析和决策辅助结果。

评估内容：

1.  自然语言问题理解和查询意图识别。
2.  NL2SQL 技术路线及候选方案。
3.  数据库 Schema、表关系和字段语义提供方式。
4.  查询范围与用户数据权限的关联。
5.  SQL 生成、语法校验和安全校验。
6.  只读查询限制、危险语句拦截和资源限制。
7.  查询结果解释、统计和聚合分析。
8.  数据可视化及图表生成。
9.  人才缺口分析和运营指标分析。
10. 分析报告生成及结果溯源。
11. 查询超时、结果过大和异常处理。
12. 数据准确性、权限隔离和审计记录。

预期交付物：

-   NL2SQL 技术方案。
-   数据权限与 SQL 安全校验方案。
-   自然语言数据查询流程图。
-   数据统计与可视化方案。
-   数据智能技术风险清单。

### 第 8 步：安全、权限与系统性能评估

**目标：** 判断平台在个人信息保护、业务权限、AI
工具执行、并发访问和系统稳定性方面是否具备合理的技术保障。

评估内容：

1.  用户认证和会话安全。
2.  用户、部门、角色和菜单权限。
3.  业务数据范围控制。
4.  候选人和员工个人信息保护。
5.  简历及上传文件的访问控制和安全检查。
6.  Agent 工具调用权限和参数校验。
7.  数字员工执行权限及敏感操作控制。
8.  NL2SQL 的只读边界和 SQL 安全机制。
9.  模型供应商密钥及敏感配置管理。
10. AI 输入输出、日志和文件中的敏感信息处理。
11. 操作日志、AI 调用日志和审计追踪。
12. 并发用户、批量任务和任务吞吐量。
13. API、模型调用及异步任务的响应时间和超时策略。
14. 数据备份、恢复、服务故障和降级机制。
15. 性能测试环境、指标口径和验收条件。

预期交付物：

-   用户与业务权限安全方案。
-   Agent 和工具安全方案。
-   数据保护与审计方案。
-   性能及资源评估报告。
-   稳定性和故障处理建议。
-   安全与非功能风险清单。

### 第 9 步：综合技术可行性评估与方案确认

**目标：**
汇总前八步的评估结论，形成平台最终技术实施基线，判断是否具备进入后续详细设计和开发阶段的条件。

评估内容：

1.  汇总七大业务领域的技术可行性。
2.  汇总总体架构和基础技术组件的评估结果。
3.  确认人才业务、测评、Agent、数字员工和数据智能的技术路线。
4.  确认业务应用层与 AI 中台的职责边界。
5.  确认数据存储、任务调度、权限和安全方案。
6.  汇总技术风险、资源限制和外部依赖。
7.  区分必须解决的问题、可后续优化的问题和暂缓事项。
8.  明确技术选型及需要保留的备选方案。
9.  梳理模块实现顺序、前置依赖和开发优先级。
10. 判断技术方案是否满足进入下一阶段的条件。

预期交付物：

-   第二阶段技术可行性评估总结。
-   最终总体技术架构图。
-   最终技术组件选型清单。
-   七大业务领域技术实现路线。
-   模块依赖及实施顺序说明。
-   技术风险与待解决事项清单。
-   下一阶段实施建议。

## 五、统一评估方法与记录规范

每个步骤统一按照以下流程开展：

1.  明确评估对象及对应业务需求。
2.  梳理当前已有方案和技术基础。
3.  分析技术原理、实现路径和依赖关系。
4.  对比推荐方案与必要的备选方案。
5.  分析优势、限制、实现难度、资源要求和风险。
6.  形成明确的可行性结论。
7.  对尚未确定的事项提出确认问题。
8.  将最终结论和证据记录到对应成果文档。

### 5.1 统一结论分类

  结论         说明
  ------------ ------------------------------------------------
  可行         当前方案能够满足需求，无需重大调整
  有条件可行   可以实现，但需要满足特定条件或补充设计
  需要调整     当前方案存在明显问题，需要调整后再推进
  待确认       缺少必要业务信息、技术信息或决策，暂时无法判断

### 5.2 技术方案记录要求

每项重要技术决策至少记录：

-   评估对象及对应业务需求。
-   当前方案。
-   推荐方案。
-   备选方案。
-   选择理由。
-   优势与不足。
-   资源及部署要求。
-   技术依赖。
-   风险与限制。
-   最终结论。
-   确认状态。

### 5.3 风险记录要求

每项风险至少记录：

-   风险编号。
-   涉及业务或技术模块。
-   风险描述及产生原因。
-   可能影响。
-   风险等级。
-   建议处理方式。
-   是否需要业务确认。
-   当前处理状态。

## 八、执行规则

1.  严格按照 01 至 09 的顺序推进，存在合理并行关系时须先说明依赖。
2.  每次只开展一个步骤，不一次性展开全部步骤的详细评估。
3.  每一步开始前，先说明评估目标、范围和需要确认的问题。
4.  需要用户决策的事项，采用分批确认方式，每批最多 6 项。
5.  已确认的需求和技术决策不重复询问；只有发现冲突或新风险时才重新确认。
6.  不把"已安装""已有设计"直接认定为"已验证可行"。
7.  不为了引入新技术而增加组件；优先评估现有方案是否满足需求。
8.  不在本阶段提前开发完整业务功能。
9.  每完成一个步骤，整理结论、更新文档并停止，等待用户明确指令后再进入下一步。
10. 所有最终结论均应区分已确认事实、推荐方案和待确认事项。
