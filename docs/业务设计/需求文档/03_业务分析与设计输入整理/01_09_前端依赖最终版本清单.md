## 4. 锁定策略

建议package.json全部22项使用精确版本，不加 ^、~ 或 *；同时提交package-lock.json，锁定传递依赖、解析结果和完整性信息。首次安装生成并审查锁文件后，团队/CI使用npm ci，清单与锁须一致；后续更新单独记录、测试并提交新锁，部署时不自动追latest。

建议后续设置项目级 `npm config set save-exact true --location=project` 并提交.npmrc，避免全局设置影响其他项目；命令仍显式--save-exact。本次不执行设置、不创建.npmrc或锁文件。团队记录Node24.21.0/npm11.19.0与Windows x64基线，CI保持相同工具版本与配置；如果改用Linux构建，另验平台二进制/可选依赖，不能以锁文件保证跨平台行为完全一致。前端构建需要开发依赖；静态服务器部署验收通过的dist产物即可。

依据：[锁文件](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/)、[npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/)、[save-exact](https://docs.npmjs.com/cli/v11/using-npm/config/#save-exact)。
