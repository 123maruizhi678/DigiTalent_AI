## 2. ECharts 评估结果

**建议保留，并作为唯一基础统计图表引擎。** 平台需要的统计和交互主要属于常规二维可视化。

| 能力 | 评估与平台用途 |
| --- | --- |
| 渲染 | 支持 Canvas、SVG；建议默认 Canvas，少量图形且确有矢量需求时再评估 SVG，不同时无条件加载两套渲染器 |
| 柱状图 | 数量、维度、结构及排名对比；堆叠柱状图呈现状态组成 |
| 折线图 | 招聘、任务、Agent 调用和运营随时间变化 |
| 饼图/环形图 | 少量互斥类别占比；多类别或多选标签优先条形图 |
| 雷达图 | 统一量纲后的能力维度对比，明确各维度满分和评分来源 |
| 散点图 | 执行耗时与调用量等两个数值指标关系；按实际分析需求启用 |
| 热力图 | 时间与类别、技能与部门等二维聚合；按需注册 VisualMap 等模块 |
| 仪表盘 | 单一目标达成率等指标；普通百分比优先指标卡或进度条，避免装饰性使用 |
| 漏斗图 | 招聘阶段转化；顺序与统计人群必须一致 |
| 数据缩放及交互 | dataZoom、tooltip、legend、brush 等支持缩放、提示和筛选；交互钻取仍须请求后端授权接口 |
| 导出 | 可通过 getDataURL 获取图像，或配置 toolbox 的 saveAsImage；由平台权限流程控制入口，不默认开放工具栏下载 |
| 大数据量 | 部分系列具备采样、大数据模式或渐进渲染能力；适用范围依具体系列及选定版本核查，不能作为无限明细下发的依据 |

官方能力介绍支持上述常规图表和交互判断，项目使用方式属于据此作出的架构建议。[ECharts 功能介绍](https://echarts.apache.org/en/feature.html)、[ECharts API](https://echarts.apache.org/en/api.html#echartsInstance.getDataURL)。

不需要为柱状、折线、饼图、雷达、漏斗等分别安装 npm 包，它们属于 echarts 内部模块。

## 3. Vue ECharts 评估结果

**建议保留 vue-echarts，作为项目统一的 Vue 封装层。**

| 评估项 | 结论及实施约束 |
| --- | --- |
| Vue 3 | 官方实现使用 Vue 3 组合式生命周期，可用于当前技术栈；后续核对所选版本 peerDependencies |
| TypeScript | 提供类型接口；业务数据 DTO 与图表 Option 类型分别定义，不额外引入 @types/echarts |
| 组件方式 | BaseChart 内部使用 VChart，统一 props、事件与容器样式 |
| 响应式更新 | option 变化驱动 setOption；建议由 computed 或替换引用构造配置，稳定 series.id；删除系列时明确合并策略，防止旧系列残留 |
| 按需引入 | 配合 echarts/core、echarts/charts、echarts/components、echarts/renderers 及 use 注册；封装层不代替模块注册 |
| 生命周期 | 官方实现提供卸载时清理；业务侧仍需释放自行建立的定时器、请求、订阅和外部监听 |
| 多实例 | 每个组件独立实例及 ref；需要联动时才设置 group，并在退出时解除自行创建的联动 |

BaseChart 不再对同一容器手工 echarts.init，也不建立全局单例图表。普通统计使用声明式 option 更新；高频大数据场景确经测试需要时再选择 manual-update，避免自动更新和手动 setOption 同时管理同一数据源。KeepAlive 停用并不等于卸载，须暂停业务刷新，激活且容器有尺寸后再 resize。

依据：[Vue ECharts 官方说明](https://github.com/ecomfe/vue-echarts)、[官方组件源码与生命周期](https://raw.githubusercontent.com/ecomfe/vue-echarts/main/src/ECharts.ts)。

## 4. 业务图表需求分析

以下为建议，不代表业务统计口径已经确认。

| 业务模块 | 需求 | 推荐展示 | 数据与口径要求 |
| --- | --- | --- | --- |
| 人才选拔 | 候选人数量统计 | 指标卡、分组柱状图、时间折线图 | 按招聘项目、岗位、时间聚合，明确候选人去重及新增/累计 |
| 人才选拔 | 招聘流程漏斗 | 漏斗图 | 同一批候选人、固定阶段顺序；跨期存量快照不能直接解释为转化漏斗 |
| 人才选拔 | 各阶段通过率 | 条形图或折线图 | 明确阶段通过人数/有效参与人数，标注样本量；分母为零显示暂无数据 |
| 人才档案与人才画像 | 人才能力 | 雷达图 | 维度归一化、满分、测评时间、来源一致；不把缺失分数当零分 |
| 人才档案与人才画像 | 标签分布 | 横向条形图、Top N | 标签可能多选，占比可超过100%；仅互斥分类使用环形图 |
| 人才档案与人才画像 | 技能结构 | 堆叠柱状图，必要时热力图 | 技能分类及等级字典统一，小样本组合抑制展示 |
| 智能测评与面试 | 测评成绩分布 | 按分数段聚合的柱状图 | 后端分桶、标注区间边界、有效成绩与缺考口径 |
| 智能测评与面试 | 维度评分对比 | 分组条形图；少量维度可用雷达图 | 同量表、可比批次、同评分规则 |
| 智能测评与面试 | 面试评价统计 | 堆叠柱状图或环形图 | 评价等级与样本量明确，不在 tooltip 暴露面试原文 |
| AI Agent 与工作流管理 | Agent 调用统计 | 时间折线图、Agent 排名条形图 | 按租户和授权范围聚合；区分调用、重试与计费次数 |
| AI Agent 与工作流管理 | 工作流执行成功率 | 指标卡、成功率趋势线 | 明确终态分母，运行中/取消状态是否排除；重试按执行还是尝试计数 |
| AI Agent 与工作流管理 | 执行耗时分析 | P50/P95/P99 趋势、耗时分桶柱状图；必要时散点图 | 后端计算分位数并统一毫秒/秒单位，避免仅均值掩盖长尾 |
| 数字员工与任务调度 | 任务执行状态分布 | 环形图、堆叠柱状图 | 待执行、运行、成功、失败、取消等状态互斥，并注明统计时点 |
| 数字员工与任务调度 | 任务执行趋势 | 折线图或按时间堆叠柱状图 | 时间粒度与时区统一，区分任务数和执行尝试数 |
| 数字员工与任务调度 | 成功率与失败率 | 双指标卡与趋势线 | 两者分母一致；存在其他终态时二者不一定相加为100% |
| 数据智能与运营决策 | 综合驾驶舱 | 指标卡、二维图表组合及筛选联动 | 统一统计时点、权限范围、刷新时间，不额外引入大屏框架 |
| 数据智能与运营决策 | 人才结构分析 | 堆叠柱状图、环形图、二维热力图 | 按组织、岗位、技能等授权维度聚合，说明缺失类别 |
| 数据智能与运营决策 | 运营趋势分析 | 多折线图、同比/环比柱状图 | 周期和时区统一，比较期完整；不同单位不直接共用单轴 |

画像图表只辅助判断，应呈现评分来源、时间与必要说明；不得将图表分数直接作为自动淘汰结论。

## 6. 图表组件架构建议

以下仅为目录规划，本次不创建任何组件或源代码。

```text
src/
├── components/
│   └── charts/
│       ├── BaseChart.vue
│       ├── TalentRadarChart.vue
│       ├── TalentDistributionChart.vue
│       ├── AssessmentChart.vue
│       └── TaskStatisticsChart.vue
```

### 6.1 分层职责

- 页面/业务数据层：调用既有 Axios 服务，负责授权范围内的数据查询、过滤条件、请求取消与重试，向图表传递 DTO、loading、error 等状态；不把接口调用埋入 BaseChart。
- 业务图表组件：负责 DTO 校验、单位转换、维度排序、空数据判定、图例和业务交互映射，将数据交给纯函数配置工厂生成 Option。
- BaseChart：封装 VChart 的容器尺寸、主题、加载/空/失败状态、公共事件、受控导出与必要的 resize 方法；不理解招聘通过率等业务口径，也不直接获取人才数据。
- 配置工厂与类型：后续可在独立 charts 配置/类型模块管理主题、颜色、模块注册和 buildXxxOption 等纯函数；DTO 与 Option 分离，不修改传入原始数据，不创建万能 JSON 配置引擎。

TalentRadarChart 负责能力维度与评分对比；TalentDistributionChart 负责人才分类和技能结构；AssessmentChart 负责成绩分布与维度评分；TaskStatisticsChart 负责状态、趋势和执行比例。招聘漏斗与 Agent 统计后续根据复用程度另设业务组件，避免将所有业务塞进现有四个文件。

### 6.2 状态与接口约定

建议 BaseChart 接收 option、loading、empty、error、height、theme、exportAllowed 等明确属性，转发点击、数据缩放及 retry 等受控事件。exportAllowed 仅是界面控制信号，不是后端权限凭证。公共样式与业务 Option 的覆盖优先级应明确，避免公共默认配置覆盖业务 series。

- 加载中：统一加载反馈；明确是否保留旧数据，并标注更新时间。
- 成功但无记录：显示暂无数据，不绘制伪造的全零图；有记录且实际为零不视为空数据。
- 比例分母为零或缺失：显示暂无有效样本，不渲染为0%；雷达缺失值不填零。
- 加载失败：区分请求失败和无数据，提供重试；不得将失败伪装成零数据。401/403 按平台策略处理，清除旧权限范围内的展示。
- 尺寸变化：显式设置可用高度，启用 VChart autoresize；覆盖侧栏、布局与容器尺寸变化。隐藏标签页显示或弹窗展开后，容器有尺寸再 resize。
- 实例管理：由 VChart 管理实例；禁止重复 init。卸载时业务层取消请求、计时器、观察器和自建事件订阅，拒绝过期请求回写。KeepAlive 单独管理暂停与恢复，实例不得跨租户长期缓存。

按需模块建议：按实际页面注册 BarChart、LineChart、PieChart、RadarChart、FunnelChart；ScatterChart、HeatmapChart、GaugeChart 有实际展示时再加入。组件按需使用 GridComponent、RadarComponent、TooltipComponent、LegendComponent、DatasetComponent、DataZoomComponent、VisualMapComponent 等，明确注册 CanvasRenderer；ToolboxComponent 仅在确有授权工具需求时使用。模块路径是包内导出，不是额外 npm 依赖。

依据：[官方按需引入与 TypeScript 指南](https://echarts.apache.org/handbook/en/basics/import/)、[容器尺寸和销毁指南](https://echarts.apache.org/handbook/en/concepts/chart-size/)。

## 7. 性能与安全要求

### 7.1 性能

1. 后端先按时间、组织等维度聚合；高基数类别使用 Top N + 其他，长趋势按时间桶采样。数据缩放不等于减少初始传输，也不等于后端分页。
2. 优先 Canvas；仅对支持的系列按需采用 sampling、large、progressive 等选项，并验证 tooltip、选中及视觉效果的限制，不全局盲目启用。
3. 按页面/业务异步加载图表，图表进入视口且容器可用时再初始化；普通无图页面不主动加载整套图表模块。按需注册与懒加载是两项不同措施。
4. 稳定系列标识，批量更新数据，避免每条消息触发整图重绘；按体量关闭或缩短动画。普通驾驶舱可先以30～60秒刷新为候选，监控页面按需求评估更短周期，此为待验证建议而非承诺。
5. 页面不可见、组件停用或权限切换时暂停刷新；采用取消请求或请求序号避免旧结果覆盖新条件；限制同时活跃图表数量。
6. 后续用代表性数据与目标浏览器测量首屏、交互、更新耗时、包体和内存。数据点上限、刷新频率及性能验收阈值尚未确定，不能声称百万点业务展示已验证。

### 7.2 安全与权限

1. 图表仅展示后端授权返回的数据；后端执行身份、租户、组织、字段及行级权限校验。前端过滤、隐藏按钮和传入组织ID均不能代替后端授权。
2. 查询、筛选、点击钻取和刷新均走受控接口；禁止获取全量数据后仅前端裁剪。权限变化或退出登录时清除图表与数据缓存，缓存键包含权限范围且不跨租户复用。
3. 优先匿名聚合，姓名、联系方式、简历、评价原文等不进入无必要的 tooltip、隐藏 series、图例或日志；小样本分组采用后端抑制或合并策略，具体阈值待确认。
4. 标签与 tooltip 内容视为不可信文本；优先文本或 richText 渲染，不把后端字符串直接拼接为 HTML，不执行后端提供的 formatter 脚本。需要 HTML 时必须使用明确的转义/净化策略。
5. 图像导出单独定义权限，默认关闭无约束的 saveAsImage。需要受控导出时先由后端校验导出权限及筛选范围、记录审计，再生成允许导出的内容；如要求强审计，使用后端导出任务。getDataURL 本身不执行身份或权限校验。
6. 浏览器已展示的数据无法通过隐藏下载按钮杜绝截图；真正边界是后端仅返回允许用户查看的数据。敏感细节不得先进入前端再期望通过导出按钮控制泄露。
