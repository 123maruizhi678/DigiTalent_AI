### 3.2 统一术语说明

- **项目群：** 项目管理的上层组织对象，用于归集和管理多个项目。
- **项目：** 可独立存在，也可归属于项目群的具体业务项目。
- **项目需求（Project Demand）：** 某个项目提出的人才数量、岗位及到岗时间等需求；项目可以独立存在，也可以归属于项目群；项目群包含多个项目，项目包含一个或多个项目需求。
- **岗位条件（Job Profile）：** 用于描述岗位要求、筛选条件和评分规则的配置。
- **简历解析（Resume Extraction）：** 从原始简历中提取个人信息、教育经历、技能及工作经验等结构化内容。
- **人才匹配（Job Matching）：** 根据岗位条件，对候选人进行条件过滤和综合评分。
- **人才画像（Talent Profile）：** 对个人能力、优势、待提升项和标签进行综合描述。
- **智能体（Agent）：** 面向具体任务的智能体，提供特定专业任务能力。
- **工作流（Workflow）：** 多个任务或智能体按照预设流程执行的工作流。
- **数字员工（Digital Worker）：** 平台中承担特定数字化业务职责的虚拟执行主体；一个数字员工可以根据职责需要关联多个 Agent 和 Workflow。
- **数字员工与 Agent 的关系：** 数字员工负责业务职责和任务组织，Agent 提供专业任务能力，Workflow 组织具体执行过程。
- **NL2SQL：** 将自然语言问题转换为数据库查询语句的技术能力。

### 3.3 统一术语规范

平台采用“中文名称为主，保留统一英文术语”的命名方式。业务文档优先使用中文名称，首次出现时可标注英文；技术实现、接口及代码中可以保留对应英文术语。

| 中文名称 | 统一英文术语 |
|---|---|
| 人才画像 | Talent Profile |
| 人才匹配 | Job Matching |
| 项目需求 | Project Demand |
| 智能体 | Agent |
| 工作流 | Workflow |
| 数字员工 | Digital Worker |

### 3.4 已确认的业务对象规则

1. **人才身份与档案：** 一个自然人对应一份人才主档案。一个账号同一时点只能对应一种业务身份；候选人录用后，账号身份转换为员工身份，保留原账号、人才主档案和候选人阶段历史业务记录。一个用户可拥有多个系统角色，系统角色与业务身份分开管理。
2. **项目层级：** 项目可以独立存在，也可以归属于项目群；项目群可包含多个项目，每个项目包含一个或多个项目需求。一个项目需求可关联多个岗位，不同岗位可以共享部分岗位条件。
3. **人才画像：** AI 根据人才资料生成画像草稿，由 HR 确认后保存为正式画像。人才关键资料发生变化时可自动生成草稿，也允许 HR 手动触发重新生成；正式画像仍需 HR 确认后更新。
4. **数字员工与 Agent：** 一个数字员工可以关联多个 Agent 和 Workflow。数字员工负责业务职责及任务组织，Agent 提供专业能力，Workflow 组织执行过程。
5. **错题复习计划：** 不纳入当前范围。智能测评保留错题记录和管理，不建设独立复习计划功能。

### 3.5 当前明确的 Agent 清单

根据现有需求及业务流程资料，目前明确列出的 Agent 如下：

| Agent 名称 | 主要职责 | 所属业务 |
|---|---|---|
| 简历解析 Agent | 调用简历解析能力，提取候选人结构化信息；解析结果进入待确认状态，由 HR 确认后写入正式人才档案 | 人才选拔 |
| 岗位匹配 Agent | 根据岗位条件执行硬性条件过滤及综合匹配评分，输出评分和匹配原因，由 HR 决定筛选结果 | 人才选拔 |

说明：

- 上表仅列出当前资料中明确出现的 Agent，不将普通业务功能直接认定为独立 Agent。
- 人才画像、测评评分、面试管理等能力是否进一步拆分为独立 Agent，应在后续具体设计时另行确定。
- Agent 应具备职责描述、工具权限、版本及运行记录等管理信息。

## 4. 核心功能范围

### 4.1 人才选拔管理

主要功能：

1. 项目人才需求管理。
2. 项目群及项目管理。
3. 岗位条件配置。
4. 岗位字典管理。
5. 简历批量上传。
6. 简历自动解析。
7. 简历解析任务管理。
8. 人才与岗位智能匹配。
9. 匹配评分及原因说明。
10. 满足及不满足条件名单管理。
11. JD 生成与发布。
12. 候选人管理。
13. 面试邀约及多轮面试管理。

### 4.2 人才档案与画像管理

主要功能：

1. 候选人及员工档案管理。
2. 人才基础信息管理。
3. 人才技能及工作经历管理。
4. AI 根据人才资料生成待确认的人才画像草稿。
5. HR 查看并确认画像草稿，确认后保存为正式人才画像。
6. 人才关键资料发生变化时，系统可自动生成画像草稿；HR 也可以手动触发重新生成。
7. 人才能力分析。
8. 人才标签管理。
9. 人才优势及待提升项管理。
10. 人才缺口统计。

### 4.3 智能测评与面试管理

主要功能：

1. 题库管理。
2. 试题管理。
3. 题目分类及难度管理。
4. 智能出卷。
5. 在线测评。
6. 客观题自动评分。
7. 主观题智能评分。
8. 测评结果管理。
9. 面试及考核结论管理。
10. 面试邀约管理。
11. 多轮面试记录管理。
12. 错题记录及管理。

### 4.4 AI Agent 与工作流管理

主要功能：

1. Agent 注册与管理。
2. Agent 状态管理及能力描述。
3. Agent 工具调用权限配置；Agent 继承所属数字员工或任务的授权范围，并可配置更细粒度权限，不得超出上层授权。
4. Agent 版本管理，支持版本创建、测试、发布、停用、历史版本查看及回滚。
5. Agent 运行记录及调用监控。
6. Workflow 定义、触发与执行。
7. 工作流固定流程、条件分支及动态任务分配。
8. 工作流状态管理及异常追踪。
9. 模型供应商管理。
10. 模型启用与停用。
11. 多智能体协作。
12. 数字员工、Workflow 与 Agent 的关联监控。

### 4.5 数字员工与任务调度

主要功能：

1. 数字员工注册管理。
2. 数字员工业务职责管理及职责流程配置。
3. 关联一个或多个 Agent 和 Workflow，组织专业能力完成业务任务。
4. 任务触发方式支持定时、周期、手动及业务事件触发。
5. 支持任务执行状态、执行记录及异常监控。
6. 任务失败后按规则自动重试；超过重试限制后记录异常、通知管理员，并支持人工重新执行或恢复。
7. 即时通信账号关联作为可选扩展能力；当前以平台内部工作台使用为主，不将外部即时通信平台作为运行前提。
8. 数字员工负责业务职责及任务组织，具体专业任务由关联 Agent 和 Workflow 执行。

### 4.6 数据智能与运营决策

主要功能：

1. 自然语言数据查询。
2. 使用 AI 模型将自然语言问题转换为只读 SQL 查询。
3. 平台在执行查询前进行用户身份、角色及业务数据范围校验。
4. 对生成的 SQL 进行安全检查，仅允许只读查询，不允许通过 NL2SQL 新增、修改或删除业务数据。
5. 业务数据统计及数据可视化。
6. 人才缺口分析。
7. 决策建议及分析报告生成。
8. 运营及审计数据查看。

**数据查询范围：** 根据用户角色和业务授权控制可查询的数据领域及数据范围。NL2SQL 只承担只读查询；业务数据修改不通过 NL2SQL 执行。

### 4.7 用户、组织与权限管理

主要功能：

1. 用户管理、部门管理、角色管理及菜单管理。
2. 角色权限配置及数据范围控制。
3. 用户生命周期管理：平台管理员负责平台用户及权限管理；HR 负责候选人邀请及招聘相关账号管理；用户可维护授权范围内的个人资料。
4. 候选人账号通过邀请方式获得，不开放自主注册；邀请采用固定有效期。发送邀请时必须向邀请发起人及候选人明确提示邀请有效期和具体失效时间；邀请过期后需重新邀请。有效期具体时长待后续配置确认。一个账号同一时点只能对应一种业务身份。
5. 敏感操作按风险等级分级审批：业务操作由相应业务负责人审批，系统级操作由平台管理员审批，特殊高风险操作可设置多级审批。
6. 人才数据导出按数据敏感程度、导出数量及用户角色分级控制；高风险批量导出需审批并记录操作日志。
7. 模型供应商配置。
8. 操作日志管理。
9. 系统运行及 AI 调用日志管理。

### 4.8 功能范围边界

- 本版本明确保留上述七个业务领域。
- 岗前培养与培训课程、企业知识库不纳入当前需求范围。
- 现有文件未明确的功能优先级、版本划分和暂缓范围，暂不设定。
- 现有接口文档中标注为“按约定推导”的接口，不视为已经完成实现或验收。
- 开发顺序采用“基础平台优先、业务分阶段建设”的方式：先建设用户权限、Agent、Workflow 等基础能力，再逐步建设人才业务、数字员工及数据智能能力。

## 5. 主要业务流程

### 5.1 人才选拔流程

项目人才需求 → 岗位条件配置 → 简历上传 → 简历解析 → 人才匹配 → 匹配结果生成 → 候选人名单管理 → JD 发布及邀约 → 面试管理 → 测评与考核 → 录用。

### 5.2 简历解析与人才匹配流程

1. HR 上传一份或多份简历。
2. 系统保存原始文件。
3. 创建简历记录和解析任务。
4. 调度器认领待处理任务。
5. 简历解析 Agent 调用解析能力。
6. 提取候选人结构化信息。
7. 保存解析结果。
8. 生成或更新人才向量。
9. 调用岗位匹配 Agent。
10. 执行硬性条件过滤及综合评分。
11. 保存匹配结果。
12. 输出满足及不满足条件的名单。

### 5.3 人才画像流程

人才档案及业务数据 → 人才信息整理 → 能力维度分析 → 人才标签关联 → 优势与不足分析 → AI 生成画像草稿 → HR 查看并确认 → 保存正式人才画像 → 人才档案更新。

人才关键资料发生变化时，系统可自动生成画像草稿；HR 也可以手动触发重新生成。正式画像必须经过 HR 确认后才能保存或更新。

### 5.4 测评与面试流程

题库维护 → 试题管理 → 创建试卷 → 根据项目或岗位配置测评与面试流程 → 候选人参与测评和/或面试 → 提交答卷 → 自动评分及智能评分 → 生成测评结果 → 面试邀约及多轮面试 → 记录面试结论。

测评与面试的先后顺序根据项目或岗位灵活配置，可先测评后面试、先面试后测评，也可根据业务需要仅安排其中一项。主观题由 AI 评分，考官可以复核和调整。

### 5.5 多智能体工作流流程

任务触发 → LangGraph 工作流启动 → 任务状态初始化 → 按预设流程执行 → 根据节点结果进行条件判断及动态分支 → 调用对应 Agent → 接收执行结果 → 更新状态 → 判断是否继续执行或进入人工审批 → 工作流完成 → 保存执行记录。

工作流采用固定流程与动态分支结合的方式；可根据任务结果选择执行分支，并在需要时进行并行执行。Agent 单次任务最长执行时间为 2 分钟。执行失败时按错误类型自动重试、人工介入或终止；Workflow 中断后支持从失败节点恢复，或由授权人员重新执行。Agent 工具权限不得超出所属数字员工或任务的授权范围。高风险操作根据风险等级进入人工审批。Agent 支持版本创建、测试、发布、停用、历史查看及回滚。系统统一监控数字员工任务、Workflow 执行过程和 Agent 调用记录，支持关联查询及异常追踪。

### 5.6 数字员工任务执行流程

数字员工注册 → 配置业务职责 → 定义职责流程 → 关联一个或多个 Agent 和 Workflow → 配置任务触发规则 → 定时、周期、手动或业务事件触发 → 创建执行任务 → 调用关联 Workflow 和 Agent → 执行业务任务 → 记录执行结果及状态 → 统一监控与异常追踪。

任务执行失败后，系统按错误类型决定自动重试、人工介入或终止；超过重试限制后记录异常并通知管理员，支持人工重新执行或恢复。权限撤销时重新校验运行任务授权，禁止后续未授权操作，并按风险暂停或终止。数字员工可选关联即时通信账号，但当前以平台内部工作台为主要使用入口。

### 5.7 智能问数流程

用户输入自然语言问题 → 识别查询意图 → 根据用户角色和业务授权获取允许访问的数据范围 → AI 生成只读 SQL → 平台执行 SQL 安全检查及权限校验 → 执行只读数据查询 → 生成统计结果 → 图表展示及分析报告。

NL2SQL 仅允许只读查询，不允许通过自然语言查询链路新增、修改或删除业务数据。查询范围受用户角色和业务授权约束。

### 5.8 用户与权限管理流程

平台管理员维护内部用户、部门及角色 → HR 发起候选人邀请 → 候选人通过邀请获得账号（邀请链接采用固定有效期；发送时提示有效期和具体失效时间，过期后需重新邀请；具体时长待确认）→ 分配用户角色 → 配置菜单、操作权限及数据范围 → 用户登录并访问授权业务功能 → 系统执行权限校验 → 按角色执行账号及个人资料管理 → 记录重要操作。

平台管理员负责平台用户及权限管理；HR 负责候选人邀请及招聘相关账号管理；用户仅可维护授权范围内的个人资料。
