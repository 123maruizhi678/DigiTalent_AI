## 1. 项目定位与目标

### 1.1 项目定位

2026 AI 数字化人才平台是一个以人工智能技术为核心的人才数字化管理与业务协作平台。
平台通过 AI Agent、RAG 知识检索、多智能体协作、自然语言数据分析等能力，将人才选拔、人才档案、人才测评、岗前培养、知识管理及数据决策等业务整合到统一平台。
平台采用前后端分离架构，通过 AI 中台统一管理智能体、工作流和模型供应商，为不同人才业务场景提供智能化支持。

### 1.2 建设目标

1. 建立统一的人才业务管理平台，整合人才选拔、人才档案、测评及培训等业务。
2. 利用 AI 技术提升简历解析、人才匹配、测评和培养计划生成等业务的自动化程度。
3. 建立统一知识库，支持企业知识资料管理、向量检索和 RAG 智能问答。
4. 建立 AI Agent 管理与工作流编排能力，实现不同业务智能体之间的协作。
5. 提供自然语言数据分析能力，辅助管理人员进行人才数据分析和业务决策。
6. 建立统一的用户、角色、部门、权限和操作审计体系。

### 1.3 建设范围

平台目前涉及以下业务领域：

- 人才选拔
- 人才档案与人才画像
- 智能测评与面试
- 岗前培养与培训课程
- 企业知识库
- AI Agent 与工作流管理
- 数字员工与任务调度
- 数据智能与运营决策
- 用户、组织与权限管理

## 2. 目标用户与使用场景

### 2.1 目标用户

根据现有设计中的用例角色，平台涉及以下用户：

| 用户角色 | 主要职责 | 使用场景 |
|---|---|---|
| 员工 | 使用个人档案、知识库、学习及测评功能 | 查看档案、知识问答、在线测评、学习 |
| HR / 招聘人员 | 负责人才选拔及招聘业务 | 简历筛选、岗位条件配置、候选人管理、面试管理 |
| 管理员 / 运维人员 | 负责平台配置和运行管理 | 用户管理、模型配置、Agent 管理、任务调度、日志审计 |
| 管理层 | 查看人才数据和业务运营情况 | 智能问数、人才缺口分析、决策建议、运营审计 |
| 候选人 | 参与招聘及考核流程 | 面试、答题、提交测评 |

### 2.2 主要使用场景

**场景一：人才招聘与筛选**

HR 根据项目人才需求配置岗位条件，上传候选人简历，系统进行简历解析和岗位匹配，输出满足及不满足条件的名单。

**场景二：人才档案管理**

系统根据候选人及员工的业务资料形成结构化档案，进一步形成能力画像、优势、待提升项和人才标签。

**场景三：智能测评**

管理人员维护题库并创建试卷，候选人或员工参与测评，系统完成评分、结果记录和错题管理。

**场景四：员工培训**

根据员工能力缺口制定岗前培养计划，关联培训课程，形成学习、考核和复盘闭环。

**场景五：企业知识问答**

员工通过自然语言查询企业知识库，系统检索相关资料并生成具有来源依据的回答。

**场景六：智能业务协作**

通过 Agent 和 LangGraph 工作流，将不同业务环节组织起来，根据任务类型调用相应智能体。

**场景七：数据分析与决策**

管理层通过自然语言查询业务数据，获取统计结果、图表和分析报告。

### 2.3 待确认事项

- 员工与候选人是否使用同一套账号体系。
- 外部候选人是否直接登录平台。
- 不同角色是否存在跨部门协作权限。
- 是否存在独立的数字员工管理角色。
- 各角色是否需要独立门户或独立操作界面。

### 3.2 统一术语说明

- **项目需求（Project Demand）：** 企业针对某个项目提出的人才数量、岗位及到岗时间等需求。
- **岗位条件（Job Profile）：** 用于描述岗位要求、筛选条件和评分规则的配置。
- **简历解析（Resume Extraction）：** 从原始简历中提取个人信息、教育经历、技能及工作经验等结构化内容。
- **人才匹配（Job Matching）：** 根据岗位条件，对候选人进行条件过滤和综合评分。
- **人才画像（Talent Profile）：** 对个人能力、优势、待提升项和标签进行综合描述。
- **RAG：** 检索增强生成，通过知识检索结果为大模型提供回答依据。
- **Agent：** 面向具体任务的智能体。
- **Workflow：** 多个任务或智能体按照预设流程执行的工作流。
- **数字员工（Digital Worker）：** 平台中承担特定数字化业务职责的虚拟执行主体。
- **NL2SQL：** 将自然语言问题转换为数据库查询语句的技术能力。

## 5. 主要业务流程

### 5.1 人才选拔流程

项目人才需求 → 岗位条件配置 → 简历上传 → 简历解析 → 人才匹配 → 匹配结果生成 → 候选人名单管理 → JD 发布及邀约 → 面试管理 → 测评与考核 → 录用或后续人才培养。

### 5.2 简历解析与人才匹配流程

1. HR 上传一份或多份简历。
2. 系统保存原始文件。
3. 创建简历记录和解析任务。
4. 调度器认领待处理任务。
5. 简历解析 Agent 调用解析能力。
6. 提取候选人结构化信息。
7. 保存解析结果。
8. 生成或更新人才向量。
9. 调用岗位匹配 Agent。
10. 执行硬性条件过滤及综合评分。
11. 保存匹配结果。
12. 输出满足及不满足条件的名单。

### 5.3 人才画像流程

人才档案及业务数据 → 人才信息整理 → 能力维度分析 → 人才标签关联 → 优势与不足分析 → 形成画像 → 人才档案更新。

具体触发条件及画像更新策略：待确认。

### 5.4 测评流程

题库维护 → 试题管理 → 创建试卷 → 用户参与测评 → 提交答卷 → 自动评分及智能评分 → 生成测评结果 → 错题归档 → 复习计划生成。

### 5.5 培训成长流程

能力缺口诊断 → 培养计划生成 → 课程关联及推送 → 学习过程 → 阶段考核 → 结果复盘 → 错题复习或能力更新 → 成长记录更新。

### 5.6 知识库构建与问答流程

知识文档上传 → 原始文件保存 → 文档解析 → 文档切片 → Embedding → 向量入库 → 建立知识关联 → 用户提出问题 → 检索及重排序 → 大模型生成回答 → 返回答案及来源。

### 5.7 多智能体工作流流程

任务触发 → LangGraph 工作流启动 → 任务状态初始化 → 判断执行分支 → 调用对应 Agent → 接收执行结果 → 状态更新 → 判断是否继续执行 → 工作流完成 → 保存执行记录。

具体 Agent 的协作关系、调用顺序及人工介入条件：待确认。

### 5.8 智能问数流程

用户输入自然语言问题 → 识别查询意图 → 获取允许访问的数据范围 → 转换为查询语句 → 执行数据查询 → 生成统计结果 → 图表展示及分析报告。

具体 SQL 安全校验及查询审批机制：待确认。

### 7.5 数据流转关系

**简历与人才数据：**

简历原文件 → MinIO → 简历解析 → 结构化结果写入 MySQL → 人才向量写入 Milvus → 人才匹配 → 匹配结果写入 MySQL。

**知识库数据：**

知识文档 → MinIO → 文档解析 → 文档切片 → 切片记录写入 MySQL → 向量写入 Milvus → 按需建立 Neo4j 关系。

**业务查询数据：**

用户请求 → 权限校验 → 业务服务 → MySQL / Milvus / Neo4j 等数据源 → 结果整理 → 返回用户。

### 7.6 数据管理要求

1. 结构化业务数据由 MySQL 统一管理。
2. 向量数据由 Milvus 管理，并保留与业务数据的关联关系。
3. 原始文件由 MinIO 管理。
4. 图谱关系由 Neo4j 管理。
5. 不同存储之间应保留必要的数据关联标识。
6. 数据更新、删除和同步机制应保持一致性。

数据保留周期、备份策略、数据脱敏、数据删除及跨库一致性策略：待确认。
