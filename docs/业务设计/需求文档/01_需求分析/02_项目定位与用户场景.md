## 1. 项目定位与目标

### 1.1 项目定位

2026 AI 数字化人才平台是一个以人工智能技术为核心的人才数字化管理与业务协作平台。

平台围绕人才选拔、人才档案与人才画像、智能测评与面试等人才业务，结合 AI Agent、多智能体协作、工作流编排、数字员工、任务调度及自然语言数据分析能力，形成统一的人才业务管理与智能协作平台。

平台采用前后端分离架构，通过 AI 中台统一管理智能体、工作流和模型供应商，为不同人才业务场景提供智能化支持。

### 1.2 建设目标

1. 建立统一的人才选拔管理能力，支持项目人才需求、岗位条件、简历解析、人才筛选及岗位匹配。
2. 建立人才档案与人才画像能力，集中管理人才基础信息、能力、优势、待提升项及标签。
3. 建立智能测评与面试管理能力，支持题库、试题、试卷、在线测评、评分及面试过程管理。
4. 建立 AI Agent 与工作流管理能力，实现智能体注册、运行、发布、协作及工作流编排。
5. 建立数字员工与任务调度能力，支持数字员工注册、职责管理、职责流程及任务调度。
6. 提供自然语言数据分析能力，辅助管理人员进行人才数据分析、人才缺口分析和业务决策。
7. 建立统一的用户、组织、角色、权限和操作审计体系。

### 1.3 建设范围

本项目当前保留以下七个业务领域：

- 人才选拔
- 人才档案与人才画像
- 智能测评与面试
- AI Agent 与工作流管理
- 数字员工与任务调度
- 数据智能与运营决策
- 用户、组织与权限管理

以下两个业务领域暂不纳入当前项目需求范围：

- 岗前培养与培训课程
- 企业知识库

## 2. 目标用户与使用场景

### 2.1 目标用户

平台采用统一账号系统，但一个账号在同一时点只能对应一种业务身份（员工或候选人）。同一自然人只建立一份人才主档案。候选人录用后，将原候选人账号身份转换为员工身份，保留原账号、人才主档案及候选人阶段的历史业务记录。一个用户可以被分配多个系统角色；业务身份与系统角色是不同概念。

外部候选人可以直接登录平台，但账号只能通过平台邀请方式获得，不开放自主注册。候选人登录后可参与招聘、面试及测评等流程，并查看授权范围内的个人信息及测评结果，不得访问内部管理功能。

平台采用分级管理方式，区分平台管理、业务管理及具体业务操作职责。

| 用户角色 | 主要职责 | 使用场景 |
|---|---|---|
| 员工 | 使用个人档案及平台授权功能 | 查看个人档案、参与在线测评、参与面试 |
| 候选人 | 通过邀请获得平台账号，参与招聘及考核流程 | 登录平台、参与面试、答题、提交测评及查看授权范围内的结果 |
| HR / 招聘人员 | 负责人才选拔及招聘业务 | 简历筛选、岗位条件配置、候选人管理、面试管理 |
| 业务管理人员 | 作为独立业务管理角色，负责相关人才业务的管理 | 人才业务管理、测评管理及业务数据管理 |
| 业务操作人员 | 根据所属业务领域及授权执行具体操作 | 处理人才选拔、档案、测评及面试等业务 |
| 平台管理员 | 负责平台整体管理、数字员工创建、授权及整体配置 | 用户与组织管理、角色权限配置、模型及平台配置、数字员工创建和授权 |
| 数字员工管理员 | 负责数字员工日常运行管理 | 数字员工职责配置、任务管理、执行监控 |
| 管理层 | 查看人才数据和业务运营情况 | 智能问数、人才缺口分析、决策建议、运营审计 |

**角色与权限管理原则：**

1. 员工与候选人使用统一账号系统，但一个账号同一时点只能对应一种业务身份；候选人录用后转换为员工身份并保留历史记录。
2. 一个自然人对应一份人才主档案；候选人和员工阶段的业务记录归集到该主档案。
3. 一个用户可以拥有多个系统角色，角色权限按授权规则合并；数据范围和明确的禁止规则仍然生效。
4. 候选人账号只能通过平台邀请方式获得，不允许自主注册；邀请必须提示有效期和具体失效日期、时间，过期后需重新邀请，具体有效时长待后续配置确认。
5. 平台采用分级管理：平台管理员负责数字员工的创建、授权及整体配置；数字员工管理员负责日常职责配置、任务管理和运行监控。
6. 业务管理人员作为独立角色设置；具体业务领域可根据需要配置相应业务操作角色。
7. 不同角色通过权限控制可访问的功能及业务数据范围；用户调部门时撤销原部门数据权限并按新部门重新分配。

**部门协作原则：**

1. 默认实行部门数据隔离，用户只能访问其权限范围内的数据。
2. 特殊项目允许通过项目授权方式开展跨部门协作。
3. 跨部门用户只能访问被授权项目及授权范围内的业务数据和功能。
4. 跨部门项目授权由平台管理员审批和授权，并支持设置授权期限。

**平台界面原则：**

平台采用统一平台、角色化工作台的方式。不同角色使用统一平台和账号体系登录，系统根据用户角色展示相应的工作台、菜单及功能入口，不为每种角色单独建设完全独立的平台。

### 2.2 主要使用场景

**场景一：人才招聘与筛选**

HR 根据项目人才需求配置岗位条件，上传候选人简历，系统进行简历解析和岗位匹配，输出满足及不满足条件的名单。

**场景二：人才档案管理**

系统根据候选人及员工的业务资料形成结构化档案，进一步形成能力画像、优势、待提升项和人才标签。

**场景三：智能测评与面试**

管理人员维护题库并创建试卷，候选人或员工参与测评，系统完成评分和结果记录；招聘人员管理面试邀约及多轮面试过程。

**场景四：智能业务协作**

通过 Agent 和工作流将不同业务任务组织起来，根据任务类型调用相应智能体，并记录执行状态和结果。

**场景五：数字员工与任务调度**

管理员配置数字员工及其职责流程，根据定时、周期或手动触发规则执行相关任务。

**场景六：数据分析与决策**

管理层通过自然语言查询业务数据，获取统计结果、图表和分析报告，辅助人才及业务决策。

**场景七：平台组织与权限管理**

管理员维护用户、部门、角色及功能权限，控制不同用户能够访问的功能和业务数据范围。平台采用统一账号体系和角色化工作台，不同角色登录后看到与其权限相匹配的工作台、菜单及功能入口。候选人账号通过邀请方式获得。部门之间默认数据隔离，特殊项目可通过项目授权开展跨部门协作。

### 2.3 原始场景确认结果

本文件原列出的六项待确认事项均已完成确认：

| 编号 | 确认事项 | 最终确认结果 |
|---|---|---|
| 1 | 员工与候选人是否使用同一套账号体系 | 统一账号体系，通过角色区分身份 |
| 2 | 外部候选人是否可以直接登录平台 | 可以登录；账号只能通过邀请方式获得，不允许自主注册 |
| 3 | 不同角色是否允许跨部门协作 | 默认部门数据隔离；特殊项目通过授权开展跨部门协作 |
| 4 | 是否设置独立的数字员工管理角色 | 采用分级管理；平台管理员负责创建、授权及整体配置，数字员工管理员负责日常职责配置、任务管理和运行监控 |
| 5 | 业务管理人员是否作为独立角色设置 | 设置独立业务管理角色，并可按业务领域配置具体操作角色 |
| 6 | 不同角色是否需要独立门户或操作界面 | 采用统一平台、角色化工作台，根据角色展示不同工作台、菜单及功能入口 |

以上确认结果已写入本文件正文。其他尚未讨论的业务细节不在本轮确认范围内，后续如需明确，可另行补充。


### 2.4 本轮需求分析补充确认

| 编号 | 确认事项 | 最终规则 |
|---|---|---|
| 1 | 账号与业务身份 | 一个账号同一时点只能对应一种业务身份；候选人录用后转换为员工身份，保留原账号及历史业务记录 |
| 2 | 人才主档案 | 一个自然人对应一份人才主档案 |
| 3 | 项目归属 | 项目可以独立存在，也可以归属于项目群 |
| 4 | 多角色 | 一个用户可以拥有多个系统角色；角色权限合并，但仍受数据范围和禁止规则约束 |
| 5 | 项目授权 | 跨部门项目由平台管理员审批和授权，并支持设置授权期限 |
| 6 | 用户停用及调部门 | 停用账号时撤销登录及相关权限并保留历史数据；调部门时撤销原部门权限并按新部门重新分配 |
| 7 | 初期用户规模 | 注册用户 100 人以内，同时在线用户 20 人以内 |

业务身份与系统角色必须区分：业务身份用于区分候选人或员工，系统角色用于分配业务职责和功能权限。一个账号不能同时处于候选人和员工两种业务身份，但同一用户可以拥有多个系统角色。
