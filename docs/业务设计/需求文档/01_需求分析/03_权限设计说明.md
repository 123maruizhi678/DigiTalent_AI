## 1. 权限设计目标

建立统一账号、组织、角色和权限体系，控制用户对平台功能、业务数据及 Agent 工具的访问和执行范围。权限控制应覆盖用户操作、业务服务、数据查询、工作流及数字员工执行。

## 2. 权限模型

采用 RBAC（基于角色的访问控制）作为基础，并结合部门、项目和个人数据范围进行数据权限控制。

权限判断至少包含：

1. 用户身份是否有效。
2. 用户拥有的角色。
3. 角色是否具有目标功能权限。
4. 用户是否具有目标数据范围权限。
5. 当前业务对象是否属于用户所属部门或已授权项目。
6. Agent、数字员工或任务是否具有对应工具执行权限。

权限不能只依赖前端菜单隐藏；后端接口、业务服务和工具执行入口均应进行权限校验。

## 3. 用户角色及职责

| 角色 | 主要职责 | 典型权限边界 |
|---|---|---|
| 员工 | 使用个人档案及被授权功能 | 个人档案、本人测评及被授权业务 |
| 候选人 | 参与招聘、测评及面试 | 本人邀请、本人资料、本人测评及授权结果 |
| HR / 招聘人员 | 人才选拔和招聘业务 | 项目人才需求、岗位条件、简历、候选人、邀约及面试 |
| 业务管理人员 | 管理所属业务领域 | 所属业务领域的配置、业务数据管理及结果查看 |
| 业务操作人员 | 执行具体业务操作 | 按所属领域和授权执行新增、查看、编辑等操作 |
| 平台管理员 | 平台整体管理 | 用户组织、角色权限、平台配置、数字员工创建及整体授权 |
| 数字员工管理员 | 数字员工日常管理 | 职责配置、任务管理、运行监控；不得自行扩大平台授权 |
| 管理层 | 经营分析及决策 | 授权范围内的统计、分析、报表及运营审计 |

一个用户可以同时拥有多个系统角色。多角色权限按授权取并集，但仍受数据范围、明确的禁止规则和敏感操作审批约束。业务身份与系统角色分开管理：一个账号同一时点只能对应候选人或员工中的一种业务身份；候选人录用后转换为员工身份并保留历史记录。

### 3.1 角色与功能权限矩阵（需求基线）

下表定义默认权限方向，实际授权仍以用户角色、业务领域和数据范围配置为准。“按授权”表示不能仅凭角色名称推定拥有全部数据权限。

| 功能领域 | 员工 | 候选人 | HR / 招聘人员 | 业务管理人员 | 业务操作人员 | 平台管理员 | 数字员工管理员 | 管理层 |
|---|---|---|---|---|---|---|---|---|
| 个人档案 | 查看本人、维护授权字段 | 查看本人、维护授权字段 | 按授权 | 按授权 | 按授权 | 管理权限配置 | 无默认权限 | 按授权查看 |
| 简历及候选人 | 无默认权限 | 提交本人资料、查看本人 | 招聘项目范围内管理 | 按授权 | 按授权 | 管理权限配置 | 无默认权限 | 授权统计数据 |
| 人才匹配 | 无默认权限 | 无权限 | 执行及查看授权项目 | 按授权 | 按授权 | 管理权限配置 | 无默认权限 | 授权统计数据 |
| 测评与面试 | 参与本人授权测评 | 参与本人测评及面试 | 按招聘项目管理 | 按授权 | 按授权 | 管理权限配置 | 无默认权限 | 授权统计数据 |
| Agent / Workflow | 无默认管理权限 | 无权限 | 无默认管理权限 | 按业务授权 | 按业务授权 | 平台级管理 | 负责授权范围内运行管理 | 授权范围查看 |
| 数字员工与任务 | 无默认管理权限 | 无权限 | 无默认管理权限 | 按业务授权 | 按业务授权 | 创建及整体授权 | 日常职责、任务和运行管理 | 授权统计查看 |
| 智能问数 | 本人/授权范围 | 无默认权限 | 招聘业务范围 | 所属业务范围 | 所属业务范围 | 按管理授权 | 仅运行管理所需范围 | 授权统计范围 |
| 用户及权限管理 | 无权限 | 无权限 | 候选人邀请及招聘账号相关管理 | 无默认平台权限 | 无权限 | 平台级管理 | 无权限 | 无权限 |

### 3.2 账号生命周期与组织变更

- 一个账号同一时点只能对应一种业务身份。候选人录用后，执行身份转换为员工，保留账号标识、人才主档案和候选人阶段业务记录。
- 用户可被分配多个系统角色，权限按授权合并，但不能突破数据范围和禁止规则。
- 用户离职或停用时，停用账号并撤销登录及相关权限，保留历史业务数据和审计记录。
- 员工调部门时，撤销原部门数据权限，按新部门重新分配；原部门历史业务记录按审计及业务归档规则保留，不代表继续授予原部门访问权。
- 跨部门项目授权由平台管理员审批和授权，必须支持设置授权期限；到期或撤销后停止相应访问。

## 4. 功能操作权限

基础操作权限包括：

| 权限编码 | 含义 |
|---|---|
| view | 查看 |
| create | 新增 |
| edit | 编辑 |
| delete | 删除 |
| export | 导出 |

功能权限应按业务模块、功能菜单及具体操作配置。对于敏感操作，除基础操作权限外，还应执行审批或二次确认规则。

## 5. 数据范围权限

| 数据范围 | 含义 | 适用说明 |
|---|---|---|
| all | 全部数据 | 仅对明确获批的管理角色开放 |
| dept | 部门数据 | 默认部门数据隔离的基础范围 |
| self | 个人数据 | 仅访问本人或本人负责范围内的数据 |
| project | 项目授权数据 | 特殊项目跨部门协作时使用，按项目及授权范围访问 |

> `project` 是根据已确认的跨部门项目授权原则补充的数据范围表达，用于落实项目级授权；具体授权字段和实现方式在详细设计中确定。

默认规则：

- 部门之间默认数据隔离。
- 跨部门协作必须基于明确的项目授权。
- 跨部门用户只能访问被授权项目及授权范围内的功能和数据。
- 候选人只能访问本人相关数据，不得访问内部管理数据。
- 数据导出权限应独立控制，不因拥有查看权限而自动获得导出权限。

## 6. Agent、Workflow 与数字员工权限

### 6.1 授权继承

- Agent 执行任务时继承所属数字员工或任务的授权上下文。
- Agent 只能在继承授权范围内调用工具。
- 工具自身还需配置细粒度权限，执行时同时校验上层授权和工具权限。
- Workflow 调用 Agent 时应传递任务身份、用户身份及授权上下文。
- 任何下游执行主体不得通过重新调用、参数变更或提示词诱导扩大权限。

### 6.2 权限校验链路

用户 / 业务请求 → 身份认证 → 角色与功能权限校验 → 数据范围校验 → 任务授权上下文 → Agent / Workflow 调用 → 工具级权限校验 → 执行 → 审计记录。

### 6.3 平台管理员与数字员工管理员分工

| 管理事项 | 平台管理员 | 数字员工管理员 |
|---|---|---|
| 创建数字员工 | 负责 | 无默认创建权限 |
| 整体授权 | 负责 | 不得扩大授权 |
| 职责配置 | 可管理 | 日常负责 |
| 任务管理 | 可管理 | 日常负责 |
| 运行监控 | 可查看和管理 | 日常负责 |
| 超出既有权限的授权变更 | 审批或配置 | 提交申请，不得自行执行 |

## 7. 敏感操作与审批

采用分级审批原则。至少应将以下操作纳入敏感操作识别范围：

- 人才档案及候选人关键信息批量导出。
- 批量删除或不可逆数据变更。
- 角色、权限及数据范围调整。
- 跨部门项目授权。
- 模型供应商、模型密钥及关键配置变更。
- Agent / 数字员工高风险工具授权。
- 可能影响候选人招聘状态或测评结论的关键操作。

审批规则按业务类型和操作风险配置审批人、审批层级及审批条件。业务操作由相应业务负责人审批，系统级操作由平台管理员审批，特殊高风险操作可设置多级审批。审批时限及具体风险分级阈值在审批流程详细设计中配置。

## 7.1 权限撤销与运行中任务

- 用户、角色或项目授权发生撤销/变更时，运行中的 Agent / Workflow 任务必须重新校验授权。
- 权限撤销后，禁止后续未授权工具调用或业务操作。
- 根据任务风险及当前执行阶段决定暂停或终止；不得以任务已启动为由继续执行已失去授权的操作。
- 任务暂停、终止、补偿及人工处理结果均应记录审计信息。

## 8. 候选人邀请权限

- 候选人账号由平台邀请产生，不开放自主注册。
- 邀请发起人应有对应招聘项目或候选人管理权限。
- 邀请记录应关联候选人、邀请发起人、邀请时间和失效时间。
- 页面及通知应显示具体失效日期和时间。
- 应向邀请发起人和候选人提示有效期。
- 邀请过期后提示重新邀请；过期邀请不得继续用于开通或登录授权。

## 9. 权限审计

以下行为应保留审计记录：

- 登录、退出及认证失败。
- 用户、部门、角色及权限变更。
- 人才档案关键字段变更。
- 数据导出、批量操作及删除。
- 跨部门项目授权及撤销。
- Agent、Workflow、数字员工配置变更。
- 工具调用及敏感操作审批。
- 智能问数的用户、查询范围、执行结果及异常。

审计记录至少应能够关联操作人、操作时间、操作对象、操作类型和执行结果。具体保存期限见《05_数据设计说明.md》。

## 10. 权限验收要点

1. 未登录用户不能访问受保护资源。
2. 无功能权限的用户不能通过直接请求接口绕过菜单限制。
3. 部门用户不能访问其他部门未授权数据。
4. 项目授权生效后，只能访问授权项目和授权范围内数据。
5. 候选人不能访问内部管理功能或其他候选人的数据。
6. Agent 不能超出数字员工或任务授权调用工具。
7. 工具级权限不足时，执行必须被拒绝并留下记录。
8. 数字员工管理员不能自行扩大平台管理员授予的权限。
9. 敏感操作按配置的审批规则执行。
10. 邀请过期后不能继续使用，且失效时间提示准确。


## 11. 本轮补充确认规则

1. 一个用户可以拥有多个系统角色，权限按授权取并集，但受数据范围和禁止规则约束。
2. 一个账号同一时点只能对应一种业务身份；候选人录用后转换为员工身份，保留原账号和业务历史。
3. 用户停用时撤销登录及相关权限，保留历史业务数据。
4. 员工调部门时撤销原部门权限，按新部门重新分配。
5. 跨部门项目授权由平台管理员审批和授权，并支持授权期限。
6. 权限撤销后，运行中的 Agent 任务重新校验授权，禁止后续未授权操作；按风险暂停或终止并记录。
7. 敏感操作根据业务类型和风险配置审批人、审批层级及规则。
