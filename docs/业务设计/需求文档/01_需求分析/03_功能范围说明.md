## 1. 项目功能定位

平台面向企业人才业务，建设统一的人才业务管理与 AI 智能协作平台。平台通过统一账号、组织、角色和权限体系，支持人才选拔、人才档案与画像、智能测评与面试、Agent 与 Workflow 管理、数字员工与任务调度、数据智能与运营决策等业务。

平台采用统一平台、角色化工作台。不同角色登录后，根据其角色、功能权限和数据范围展示相应菜单及业务入口。

## 2. 本期业务范围

本期保留七个业务领域：

1. 人才选拔管理
2. 人才档案与人才画像
3. 智能测评与面试管理
4. AI Agent 与工作流管理
5. 数字员工与任务调度
6. 数据智能与运营决策
7. 用户、组织与权限管理

明确不纳入当前需求范围：

- 岗前培养与培训课程
- 企业知识库
- 错题复习计划

## 3. 各业务领域功能范围

### 3.1 人才选拔管理

**功能范围**

- 项目群、项目及项目人才需求管理。
- 岗位字典和岗位条件管理。
- 简历文件上传、存储、解析任务管理；单次批量上传最多 20 份。
- 简历结构化信息提取及解析结果管理；同一人才可关联多份简历，并区分来源、用途及有效状态，保留历史版本和解析记录。
- 人才与岗位匹配、匹配评分及原因说明。
- 满足和不满足条件的候选人名单管理。
- JD 生成与发布。
- 候选人管理。
- 面试邀约及多轮面试管理。
- 候选人邀请采用固定有效期；邀请页面及相关通知应显示具体失效日期和时间，并向邀请发起人及候选人提示。邀请过期后提示重新邀请。

**业务规则**

- 项目可以独立存在，也可以归属于项目群；项目群用于归集多个项目。
- 项目下可以包含一个或多个项目需求；一个项目需求可以关联多个岗位。
- 多个岗位可以共享部分岗位条件，也可以配置各自独立的条件。
- 项目关闭后保留历史数据，管理员可以重新开启。
- 项目层级不要求每个项目必须归属项目群。
- AI 生成的 JD 或相关招聘内容作为草稿，须由 HR 确认后再发布。
- 简历匹配结果用于辅助筛选，应保留匹配评分及原因，不能只输出无依据的结论。
- 候选人账号通过平台邀请获得，不开放自主注册；邀请需显示有效期和具体失效日期、时间，过期后提示重新邀请，具体时长待配置确认。
- 简历解析失败时自动重试；达到重试上限后标记失败，允许人工重新发起。
- AI 解析结果先进入待确认状态，由 HR 确认后写入正式人才档案。
- AI 匹配输出评分、匹配原因及推荐名单，由 HR 决定筛选结果。

**不在本节擅自确定**

- 具体匹配算法、评分权重和阈值。
- 邀请固定有效期的具体时长。
- JD 发布渠道及第三方招聘平台对接范围。

### 3.2 人才档案与人才画像

**功能范围**

- 候选人及员工统一人才主档案管理。
- 人才基础信息、教育经历、技能及工作经历管理。
- 人才能力画像生成与更新。
- 人才标签管理。
- 人才优势、待提升项管理。
- 人才缺口统计及相关人才分析。

**业务规则**

- 一个自然人对应一份人才主档案，候选人和员工阶段的业务记录归集到该档案。
- 一个账号同一时点只能对应一种业务身份；候选人录用后将账号身份转换为员工身份，保留原档案及候选人阶段历史记录。
- AI 生成画像草稿，必须由 HR 确认后才能生效；人才关键资料变化可自动生成新草稿，也允许 HR 手动触发重新生成。
- 正式画像保留历史版本；人工调整及每次确认均保留变更记录。
- 画像生成结果应能够追溯其依据的数据或业务记录；人工调整应保留必要的变更记录。

### 3.3 智能测评与面试管理

**功能范围**

- 题库、试题、题目分类及难度管理。
- 试卷创建及智能出卷。
- 在线测评、答卷提交。
- 客观题自动评分。
- 主观题智能评分。
- 测评结果管理。
- 面试邀约、多轮面试记录及面试结论管理。
- 错题记录及查询。

**业务规则**

- 测评与面试采用可配置的业务流程，允许根据不同招聘或人才项目设置先后顺序及必要环节。
- 测评、面试结果应分别记录，并能够关联到对应人才档案及招聘项目。
- 主观题由 AI 提供评分，考官可以复核和调整，最终成绩应记录复核结果。
- 本期不建设错题复习计划。

### 3.4 AI Agent 与工作流管理

**功能范围**

- Agent 注册、信息维护、能力描述及状态管理。
- Agent 发布与应用管理。
- Agent 运行记录、执行状态和结果查询。
- Workflow 定义、触发、执行及状态管理。
- 多 Agent 协作。
- 模型供应商及模型启停管理。
- 定时、周期和手动任务触发能力。
- Agent 调用工具及执行权限管理。

**业务规则**

- 工作流采用固定主流程与动态分支相结合的方式。
- Agent 执行工具调用时继承其所属数字员工或任务的授权上下文，并受到工具级细粒度权限约束。
- Agent 不得仅凭模型输出自行扩大权限。
- 业务影响操作按风险等级区分：普通且已授权操作可执行；敏感操作需人工确认或审批。
- 单次 Agent 任务最长执行时间为 2 分钟；超时按错误类型进入重试、人工介入或终止处理。
- Agent 失败时按错误类型决定自动重试、人工介入或终止，并记录每次执行过程。
- Workflow 支持从失败节点恢复，也允许有权限人员选择重新执行；恢复或重执行前需防止已成功节点造成重复业务操作。
- 具体 Agent 清单应以代码、配置和实际运行记录盘点结果为准。当前两份输入文件没有提供已实现 Agent 的正式名称清单。

**现有资料中能够识别的 Agent 业务能力（属于流程中提及的能力，不代表已开发完成）**

| 能力名称（暂定） | 对应业务 | 当前依据 |
|---|---|---|
| 简历解析 Agent | 简历解析与结构化提取 | 需求文档 5.2 |
| 岗位匹配 Agent | 人才与岗位匹配 | 需求文档 5.2 |
| 测评评分 Agent / 评分能力 | 答卷评分 | 需求文档 6.2 |
| 数据查询 Agent / 查询能力 | 自然语言数据查询 | 需求文档 6.2、5.7 |
| 其他业务 Agent | 由后续业务流程确定 | 当前资料未给出正式清单 |

> 上表是从业务流程和工具能力归纳出的能力项，不能直接作为“当前已上线 Agent”清单。正式清单需要结合项目代码及配置盘点后补充。

### 3.5 数字员工与任务调度

**功能范围**

- 数字员工注册、信息维护。
- 数字员工职责配置。
- 职责流程定义。
- 数字员工与多个 Agent、Workflow 的关联。
- 任务触发规则配置。
- 任务执行状态、结果及异常记录。
- 数字员工日常运行管理。

**业务规则**

- 平台管理员负责数字员工创建、整体配置及授权。
- 数字员工管理员负责日常职责配置、任务管理和运行监控。
- 一个数字员工可以根据职责关联多个 Agent 或 Workflow。
- 任务触发支持定时、周期和手动方式；具体已确认的业务事件触发能力按对应工作流配置。
- 数字员工管理员只能在已有授权范围内管理任务和职责，不得自行扩大权限。
- 权限被撤销时，运行任务需重新校验授权，禁止后续未授权操作；按任务风险暂停或终止并记录。
- 数字员工的实际执行权限不得超过其被授予的权限。

### 3.6 数据智能与运营决策

**功能范围**

- 自然语言业务数据查询。
- 自然语言转 SQL。
- 业务数据统计及可视化。
- 人才缺口分析。
- 决策建议。
- 分析报告生成。
- 运营及审计数据查看。

**业务规则**

- 采用 AI 生成查询 SQL、平台进行安全与权限校验后执行的方式。
- SQL 必须经过平台校验，不能由模型直接绕过业务服务访问数据库。
- 查询结果必须受当前用户的数据范围约束。
- 涉及写入、修改或删除的 SQL 不属于普通智能问数能力。
- AI 生成的查询 SQL 必须经过安全检查和用户权限校验后才可执行。

### 3.7 用户、组织与权限管理

**功能范围**

- 用户、部门及组织信息管理。
- 统一账号体系。
- 角色管理及角色分配。
- 菜单、功能和数据范围权限配置。
- 候选人邀请及账号开通管理。
- 操作日志、系统日志及 AI 调用日志管理。
- 平台基础配置管理。

**业务规则**

- 员工与候选人使用统一账号系统，但一个账号同一时点只能对应一种业务身份；候选人录用后转换为员工身份并保留历史记录。
- 一个用户可以拥有多个系统角色；角色权限按授权合并，但数据范围和禁止规则仍然生效。
- 候选人仅能通过邀请获得账号。
- 默认部门数据隔离；特殊项目通过平台管理员审批的项目授权开展跨部门协作，并设置授权期限。
- 用户停用时撤销登录和相关权限，保留历史业务数据；员工调部门时撤销原部门权限，按新部门重新分配。
- 统一平台、角色化工作台，不为每种角色单独建设完全独立的平台。

## 4. 业务流程范围

本期至少覆盖以下端到端流程：

1. 项目（可独立存在或归属项目群）→ 项目需求 → 多岗位及岗位条件 → 简历上传 → 简历解析 → 人才匹配 → 候选人管理。
2. 候选人邀请 → 候选人登录 → 参与测评或面试 → 结果记录。
3. 人才业务数据 → 人才档案 → AI 画像生成 → 人工维护及更新。
4. 题库 → 试题 → 试卷 → 测评 → 评分 → 结果记录。
5. Agent 注册及授权 → Workflow 编排 → 任务触发 → Agent 执行 → 结果及日志记录。
6. 数字员工创建 → 职责配置 → 关联 Agent / Workflow → 任务触发 → 执行监控。
7. 自然语言问题 → 查询意图识别 → SQL 生成 → 权限及安全校验 → 查询 → 结果展示。
8. 用户、部门、角色配置 → 权限分配 → 业务访问 → 权限校验 → 操作审计。

## 6. 本期运行规模与处理约束

- 初期注册用户规模：100 人以内。
- 初期同时在线用户规模：20 人以内。
- 单次批量简历上传：最多 20 份。
- Agent 单次任务最长执行时间：2 分钟；超时进入异常处理。
- 系统本期不设固定可用性百分比，但必须具备核心服务监控、异常告警及恢复机制。
- 数据每天备份一次，并定期验证恢复能力。

## 7. 功能范围变更原则

1. 新增功能应说明所属业务领域、业务对象、使用角色、数据影响及验收方式。
2. 变更既有功能时，应同步检查权限、数据模型、业务流程和验收用例。
3. 不因某项功能在原始设计中出现，就默认其已经实现或必须在当前版本交付。
4. 未确认事项不得作为已完成的验收承诺。
5. 本文件与权限、数据及验收文件共同构成需求基线。
