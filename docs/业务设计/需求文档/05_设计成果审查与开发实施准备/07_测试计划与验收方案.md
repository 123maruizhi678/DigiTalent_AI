## 一、目标、范围与原则

### 1.1 本步骤目标

建立覆盖开发过程、模块集成、AI能力、安全可靠性和业务验收的完整质量保障体系，明确：

1. 测试组织方式与执行策略；
2. 测试环境和测试数据管理；
3. 功能、数据库、API、前端和AI测试要求；
4. 七大业务模块测试范围；
5. Agent、Workflow、Worker及调度可靠性测试；
6. 权限、安全、隐私和审计测试；
7. 性能、稳定性和异常恢复测试；
8. 端到端业务场景和用户验收标准；
9. 缺陷管理、测试报告和发布准入规则。

### 1.2 七大业务范围

1. 人才选拔；
2. 人才档案与人才画像；
3. 智能测评与面试；
4. AI Agent与工作流管理；
5. 数字员工与任务调度；
6. 数据智能与运营决策；
7. 用户、组织与权限管理。

当前范围明确不包含岗前培养与培训课程、企业知识库。不得因测试需要将其扩展为本项目业务模块。

### 1.3 测试原则

- **质量左移：** 任务开发过程中同步设计和执行测试，不等全部开发结束再集中发现问题。
- **分层验证：** 单元、组件、数据库、API、模块集成、端到端和用户验收逐层推进。
- **业务闭环优先：** 首期重点验证基础平台、人才选拔、人才档案与画像的端到端流程。
- **AI结果可评估：** 使用经审核的测试样本、人工标注和明确指标，不以输出流畅或单次体验作为验收。
- **安全默认开启：** 权限、数据范围、文件访问和敏感信息保护属于功能验收的一部分。
- **证据可追溯：** 每个测试结果关联版本、环境、用例、数据、执行记录和缺陷。
- **不虚构阈值：** 本文件给出指标类别和阈值确定方式，尚未确认的具体数字在基准测试后另行批准。
- **失败可复现：** 测试失败应保留必要的脱敏输入、日志关联标识、执行版本和复现步骤。

## 三、测试体系与执行流程

### 3.1 测试体系结构

测试按统一层次组织，并映射到七大业务模块：

| 测试层次 | 主要对象 | 主要目的 |
|---|---|---|
| 静态质量检查 | Python、TypeScript、配置和依赖 | 尽早发现类型、格式、依赖和安全问题 |
| 单元测试 | Service、Repository、规则、工具函数、Schema | 验证最小逻辑单元 |
| 前端组件测试 | 公共组件、表单、表格、状态组件 | 验证组件输入、输出和交互 |
| 数据库测试 | ORM、约束、事务、迁移、索引 | 验证数据结构与持久化行为 |
| API契约测试 | FastAPI接口、请求响应Schema | 验证接口与设计契约一致 |
| 模块集成测试 | 模块内服务、数据库、文件、AI和Worker | 验证组件协作 |
| 端到端测试 | 完整人才业务流程 | 验证系统整体业务可用性 |
| AI效果测试 | MinerU、模型、Embedding、Agent、Workflow | 验证AI输出质量和执行可靠性 |
| 安全测试 | 认证、授权、文件、日志、Tool和数据 | 验证安全边界 |
| 性能可靠性测试 | API、数据库、解析、模型、Worker | 验证负载、稳定性和恢复能力 |
| 用户验收测试 | 业务角色、管理员、候选人等 | 验证是否满足业务需求 |

### 3.2 测试执行流程

```text
需求/设计确认
    ↓
建立测试范围与验收标准
    ↓
准备环境、测试数据和测试账号
    ↓
开发任务级测试
    ↓
模块集成测试
    ↓
缺陷登记、修复与定向回归
    ↓
端到端业务测试
    ↓
安全、性能、可靠性专项测试
    ↓
用户验收测试
    ↓
版本准入评审
    ↓
测试报告与验收归档
```

### 3.3 每项开发任务的测试要求

任务进入“待验收”前，至少应具备：

- 对应测试用例；
- 正向、反向、边界和异常场景；
- 自动化测试结果或人工执行证据；
- 相关API、数据库和权限验证结果；
- 未通过项及缺陷关联；
- 必要的测试数据清理结果；
- 文档和接口契约更新情况。

## 四、测试环境与测试数据管理

### 4.1 环境分层

| 环境 | 用途 | 数据要求 |
|---|---|---|
| 开发环境 | 开发人员快速验证 | 优先使用合成数据 |
| 测试环境 | 自动化测试、模块集成和回归 | 使用可重置的测试数据集 |
| 验收环境 | 业务人员执行UAT | 使用经批准的脱敏或合成数据 |
| 生产环境 | 正式业务运行 | 不作为常规测试环境 |

环境配置结构和值遵循第五阶段第06步已确认决策：各环境配置值保持一致。敏感凭据仍须通过安全方式注入，不得写入代码仓库、测试报告或普通日志。若部署隔离导致某项配置无法保持一致，应在实施时提出决策变更，不自行绕过。

### 4.2 测试数据分类

1. **合成数据：** 人工生成的候选人、岗位、经历、技能、题目和任务数据。
2. **脱敏样本：** 从经授权的数据中去除或替换可识别个人身份的信息。
3. **授权真实样本：** 仅在有明确合法依据、访问授权和使用范围时使用。
4. **边界数据：** 空值、超长字段、特殊字符、重复记录、异常文件、极端分值和大批量记录。
5. **安全测试数据：** 专门构造的越权、恶意文件、异常输入和提示注入样本。

### 4.3 数据保护要求

- 仅收集测试必需字段；
- 测试账号按角色和数据范围隔离；
- 不将生产简历、面试记录或个人信息直接复制到开发环境；
- 测试数据设置保留期限和清理责任；
- 测试报告、截图和日志不得泄露个人敏感信息；
- 数据导出、复制和共享应有授权和记录；
- 验收结束后按规则清理或归档测试数据；
- 测试数据与正式业务数据明确区分，避免误发通知或触发真实业务动作。

### 4.4 测试数据集管理

每个数据集至少记录：

- 数据集编号和版本；
- 业务模块和测试目的；
- 数据来源和授权依据；
- 脱敏方式；
- 字段说明和数据规模；
- 适用测试用例；
- 创建时间、责任人和保留期限；
- 校验摘要或版本标识。

## 五、功能、数据库、API与前端测试

### 5.1 功能测试通用设计

每个功能至少考虑：

| 场景类型 | 示例 |
|---|---|
| 正向场景 | 正常输入、正常权限、有效状态下成功执行 |
| 反向场景 | 无权限、状态不允许、业务规则不满足 |
| 边界场景 | 空值、最大长度、最小值、最大值、分页边界 |
| 异常场景 | 下游服务不可用、超时、数据库异常、文件损坏 |
| 幂等场景 | 重复点击、重复提交、请求重放 |
| 并发场景 | 两个用户同时修改、重复领取任务 |
| 状态流转 | 非法状态跳转、重复审核、已完成任务再次执行 |
| 数据一致性 | 主从对象关联、删除限制、版本和来源完整 |

### 5.2 数据库测试

覆盖：

- SQLAlchemy模型与数据库字段映射；
- 主键、唯一约束、外键和非空约束；
- 索引与关键查询；
- 事务提交、回滚和隔离行为；
- 并发更新和乐观/悲观锁策略（如设计采用）；
- Alembic从空库升级；
- 已有版本逐级迁移；
- 迁移失败后的恢复策略；
- 迁移后数据完整性；
- 备份和恢复演练；
- 大数据量下的关键查询表现。

数据库测试必须遵循已确认的数据库详细设计，不因测试方便而擅自增加业务表或改变存储归属。

### 5.3 API接口测试

每个接口验证：

- HTTP方法、路径和版本；
- 请求字段类型、必填和边界；
- 响应结构和字段含义；
- 状态码和统一错误格式；
- 认证和角色权限；
- 数据范围过滤；
- 分页、排序和过滤；
- 幂等键或重复请求行为（适用时）；
- 超时、下游失败和异常映射；
- 并发修改与状态冲突；
- OpenAPI契约与实现一致性。

API契约变化时，必须同步更新后端Schema、前端类型、Mock数据和测试用例。

### 5.4 前端测试

覆盖：

- 路由访问和权限守卫；
- 登录、邀请和会话失效；
- 表单必填、格式、边界和错误提示；
- 表格分页、筛选、排序和空状态；
- 加载、成功、失败和重试状态；
- 异步任务进度和刷新后状态恢复；
- 多标签切换、关闭和刷新；
- 文件上传、预览和下载；
- 无权限页面和无数据页面；
- 浏览器控制台错误；
- API失败时的用户反馈。

前端隐藏菜单不等于安全控制，所有后端接口必须独立完成授权校验。

### 5.5 文件与文档解析测试

覆盖：

- 支持格式：Markdown、PDF、DOCX、HTML；
- 扩展名与实际文件内容不一致；
- 空文件、损坏文件、加密文件和超大文件；
- 文件名特殊字符和路径穿越尝试；
- 上传中断、重复上传和下载中断；
- 文件元数据与业务对象关联；
- 文件权限和下载鉴权；
- MinerU超时、服务不可用和异常响应；
- 解析结果为空、部分成功和结构异常；
- 表格、标题、页码、代码块和图片引用等结构保留；
- 解析失败时保留原始文件并提供可诊断状态。

## 六、七大业务模块测试范围

### 6.1 人才选拔

- 项目、项目群、岗位和招聘需求的创建、修改、归档和状态流转；
- 候选人创建、重复识别和关联；
- 简历上传、文件关联和解析任务；
- 解析字段准确性、缺失值和人工修正；
- 智能筛选规则命中、筛选依据和人工复核；
- 人岗匹配维度、差距、解释和结果版本；
- 招聘阶段流转和操作权限；
- 批量处理、失败重试和重复提交；
- 招聘人员只能访问授权项目和候选人数据。

### 6.2 人才档案与人才画像

- 候选人与人才主档关联，避免重复自然人主档；
- 人才经历类型、时间范围和数据完整性；
- 技能字典、标签字典和关联关系；
- 档案来源、数据变更和历史追踪；
- 画像生成输入范围和数据来源；
- 画像事实与推断区分；
- 画像版本、审核、驳回、修改和发布；
- 未审核画像不得被当作正式画像使用；
- 画像访问和导出权限。

### 6.3 智能测评与面试

- 测评方案、题库和试题管理；
- 方案与试题关联、顺序、分值和抽题规则；
- 测评任务执行时配置快照；
- 答题提交、重复提交和截止状态；
- 客观题规则评分；
- 主观题AI辅助评分和人工复核；
- 多轮面试记录、面试评价和面试报告；
- 报告生成失败和重新生成；
- 候选人、面试官和管理员权限隔离。

### 6.4 AI Agent与工作流管理

- 模型适配器切换和模型不可用；
- Prompt版本、输入输出Schema和变量缺失；
- Tool参数校验、权限和调用边界；
- Agent执行状态、异常和结果；
- Workflow节点顺序、条件分支和状态传递；
- Checkpoint持久化、中断和恢复；
- 人工审核节点等待、批准、拒绝和超时；
- 循环、最大步数和资源限制；
- 执行记录摘要与日志文件关联；
- 敏感提示、提示注入和不可信输入处理。

### 6.5 数字员工与任务调度

- 数字员工创建、启停和能力关联；
- 任务分配、计划触发和执行状态；
- APScheduler触发行为（如采用）；
- Worker任务认领和并发；
- 重复触发、幂等和任务去重；
- 任务超时、取消、重试和失败恢复；
- Worker进程退出后的任务状态；
- 数字员工只能调用授权Agent、Workflow和Tool；
- 执行审计和结果追踪。

### 6.6 数据智能与运营决策

- 指标定义、口径、维度和时间范围；
- 统计结果与业务明细抽样核对；
- 组织和数据范围过滤；
- 图表空值、零值、异常值和时间边界；
- 分析任务状态和失败恢复；
- 报告生成、文件关联和下载权限；
- NL2SQL（如启用）的只读限制、表/字段白名单、查询超时、行数限制和敏感字段过滤；
- AI生成分析结论的来源和可复核性。

### 6.7 用户、组织与权限管理

- 邀请制账号创建和激活；
- 登录、Token过期和退出；
- 用户、组织、部门、角色和权限关系；
- 菜单权限、操作权限和数据范围权限；
- 角色变更即时生效策略；
- 用户禁用、离职或组织变更后的访问控制；
- 跨组织访问和水平越权；
- 管理员高风险操作的审计；
- 无权限时的统一拒绝行为。

## 七、AI能力与效果评估方案

### 7.1 AI评估基本要求

- 测试集按任务类型建立，不将所有AI任务混为一个总分；
- 测试集应有人工标注结果和标注规则；
- 训练/调优样本与最终评估样本隔离；
- 保存模型名称、版本、参数、Prompt版本和执行时间；
- 同一评估集在模型或Prompt变更后重复执行；
- 对高影响结果保留人工审核；
- 评估结果需记录失败案例，不只记录平均分。

### 7.2 主要AI任务指标

| AI任务 | 主要指标 | 评估方式 |
|---|---|---|
| 简历结构化解析 | 字段准确率、字段完整率、日期/实体抽取正确率 | 与人工标注字段逐项比对 |
| 简历智能筛选 | 规则命中率、精确率、召回率、误筛率 | 与业务标注的筛选结果比对 |
| 人岗匹配 | 排序质量、维度一致性、解释完整性 | 与业务专家评估结果对比 |
| 人才画像 | 事实准确性、来源覆盖率、推断标识率、幻觉率 | 逐条核验画像陈述和来源 |
| 测评辅助分析 | 评分一致性、评分偏差、证据充分性 | 与人工评分及复核结果比较 |
| 面试分析 | 关键信息覆盖率、证据引用正确率、总结准确性 | 与面试记录人工标注比对 |
| 运营分析 | 数值准确率、SQL安全性、结论可追溯性 | 与基准查询和业务口径比对 |

具体目标阈值不在缺乏业务样本时臆定。每类AI能力上线前，应由业务负责人和技术负责人根据基准集确定最低通过阈值、关键字段阈值和不可接受错误类型。

### 7.3 AI安全与公平性检查

- 不将模型推断当作已核实事实；
- 不因模型输出直接作出未经人工确认的录用/淘汰决定；
- 对与岗位无关或可能造成不公平影响的个人属性进行限制；
- 检查提示注入和恶意文档内容；
- 检查模型是否泄露系统提示、其他候选人数据或敏感字段；
- 检查生成内容是否存在无来源断言；
- 对高风险结论提供依据、来源和人工复核入口。

### 7.4 AI效果报告

每次评估至少记录：

- 测试集编号和版本；
- 模型供应商、模型名称和版本；
- Prompt/Workflow版本；
- 参数配置；
- 测试任务和样本规模；
- 指标定义和阈值；
- 实际结果和失败案例；
- 人工复核结论；
- 与上一版本的差异；
- 是否达到发布标准。

## 八、Agent、Workflow、Worker与异步任务可靠性测试

### 8.1 Agent与Tool

- Tool输入缺字段、字段类型错误和越界参数；
- Tool无权限、权限过期和跨组织资源访问；
- Tool超时、异常、返回空值和格式不符合Schema；
- 重复调用和幂等；
- 不可信文档中的提示注入；
- Agent超过最大步数或陷入循环；
- Agent调用失败后是否按规则终止或重试；
- Agent结果是否经过业务Schema校验。

### 8.2 Workflow与Checkpoint

- 正常节点顺序和条件分支；
- 分支条件边界和默认路径；
- 中断后恢复；
- Checkpoint写入失败；
- 从旧Checkpoint恢复时版本不兼容；
- 并发执行和重复恢复；
- 人工审核等待、拒绝和批准；
- 任务取消后是否继续执行；
- 恢复后是否重复产生副作用；
- 节点执行摘要和结构化日志关联。

### 8.3 Worker与调度

- 任务被多个Worker同时认领；
- Worker执行中进程退出；
- 任务超时；
- 任务重复投递；
- 重试次数达到上限；
- 取消与执行完成同时发生；
- 服务重启后未完成任务的处理；
- 下游服务不可用时的退避策略；
- 任务状态与实际业务结果一致性。

## 九、安全、隐私、审计与日志测试

### 9.1 认证与授权

- 未登录访问受保护接口；
- Token伪造、过期、撤销或签名错误；
- 普通用户访问管理员接口；
- 同角色用户访问不属于其数据范围的对象；
- 跨组织、跨项目、跨候选人访问；
- 通过修改URL、ID或请求体尝试水平越权；
- 前端隐藏功能但后端未授权的情况；
- 用户禁用或权限变更后的访问行为。

### 9.2 文件安全

- 上传非允许格式、伪造MIME类型和扩展名；
- 文件名路径穿越；
- 超大文件和压缩炸弹风险；
- 恶意内容和提示注入文档；
- 未授权下载和猜测文件ID；
- 文件删除后残留引用；
- 文件存储路径或内部主机路径泄露。

### 9.3 敏感信息保护

- 密码、Token、API密钥不进入普通日志；
- 简历、联系方式、面试内容按权限展示；
- 导出文件按数据范围过滤；
- 测试报告和截图进行脱敏；
- 模型请求只发送任务必需数据；
- 外部模型调用前检查数据授权和传输边界；
- 错误信息不泄露堆栈、SQL、密钥或内部路径。

### 9.4 审计与日志

根据数据库详细设计，操作审计及运行过程记录按已确认的日志文件存储原则实施，不为方便测试而擅自新增数据库日志表。

测试检查：
- 关键操作是否记录操作者、对象、时间和结果；
- request_id、task_id、execution_id是否可关联；
- 日志级别和分类是否合理；
- 敏感字段是否脱敏；
- 日志轮转、保留和归档是否有效；
- 日志写入失败是否有降级或告警；
- 普通用户是否不能读取不属于其权限范围的日志；
- 日志内容是否足以支持故障定位而不泄露过多信息。

## 十、性能、兼容性与稳定性测试

### 10.1 性能测试对象

| 对象 | 主要测试内容 |
|---|---|
| FastAPI接口 | 响应时间、吞吐量、并发和错误率 |
| MySQL | 慢查询、索引、连接池、事务和并发 |
| 文件服务 | 上传下载速度、并发、文件大小和磁盘IO |
| MinerU | 解析耗时、并发、超时和资源占用 |
| Ollama模型 | 首Token时间、总耗时、并发和显存/内存 |
| Embedding | 批量吞吐、维度和失败率 |
| Milvus | 插入、索引、检索延迟和过滤效果 |
| Worker | 任务吞吐、排队时间、失败率和恢复时间 |
| 前端 | 首屏、路由切换、长列表和大数据展示 |

### 10.2 性能指标与阈值

每类接口和任务应在建立基准后确定：
- 平均响应时间；
- P50、P95、P99延迟；
- 吞吐量；
- 并发数；
- 超时率和错误率；
- CPU、内存、显存和磁盘使用；
- 队列等待时间；
- 任务成功率和恢复时间。

不得在没有真实业务规模、硬件和模型基准的情况下编造统一性能承诺。首期先形成基线，再经业务和技术评审批准目标值。

### 10.3 稳定性测试

- 连续运行和长时间任务；
- 模型服务重启；
- MySQL短暂不可用；
- Milvus不可用；
- MinerU超时或崩溃；
- Worker被终止；
- 网络中断和恢复；
- 磁盘空间不足；
- 日志轮转期间写入；
- 任务执行中应用重启；
- 数据库迁移期间服务控制。

### 10.4 兼容性测试

- 约定支持的桌面浏览器版本；
- Markdown、PDF、DOCX、HTML文件；
- 不同文件大小和复杂结构；
- 本地模型和云端模型适配器；
- 依赖库和服务版本组合；
- 数据库迁移版本；
- 前端构建产物和部署路径。

## 十一、端到端业务测试场景

### 11.1 首期核心场景A：账号与权限

1. 管理员创建用户并发送邀请；
2. 用户完成邀请激活和登录；
3. 系统返回当前用户及授权范围；
4. 前端按权限展示菜单和路由；
5. 用户访问允许的项目和候选人；
6. 用户尝试访问未授权对象；
7. 后端拒绝请求并形成必要审计记录。

**通过标准：** 邀请制有效、授权正确、越权被拒绝、关键操作可追踪。

### 11.2 首期核心场景B：简历解析

1. 招聘人员创建项目、岗位和招聘需求；
2. 创建或选择候选人；
3. 上传PDF/DOCX等支持格式的简历；
4. 文件服务保存文件本体和元数据；
5. 创建异步解析任务；
6. Worker调用MinerU；
7. 系统保存解析结果和任务状态；
8. 招聘人员查看并修正结构化结果；
9. 用户确认解析结果。

**通过标准：** 文件引用正确、解析结果可复核、失败可追踪、原始文件保留、权限有效。

### 11.3 首期核心场景C：智能筛选与人岗匹配

1. 选择招聘需求和候选人范围；
2. 提交智能筛选任务；
3. Workflow执行规则与AI分析；
4. 返回筛选结论、依据和不确定项；
5. 人工复核筛选结果；
6. 发起人岗匹配；
7. 查看匹配维度、差距和解释；
8. 人工确认并更新业务阶段。

**通过标准：** 结果结构正确、规则口径一致、依据可追溯、人工决定与AI建议区分。

### 11.4 首期核心场景D：人才档案与画像

1. 将候选人与人才主档关联；
2. 维护教育、工作和项目经历；
3. 维护技能与标签；
4. 触发画像生成；
5. 生成待审核画像版本；
6. 审核人员核对事实和来源；
7. 修改或驳回不准确内容；
8. 审核通过并发布；
9. 查询历史画像版本。

**通过标准：** 人才主体唯一、来源清晰、画像版本可追溯、未经审核的画像不被当作正式结果。

### 11.5 后续业务场景

- 测评方案创建、任务分配、答题、评分和报告；
- 多轮面试记录、AI辅助分析和人工评价；
- Agent注册、Tool调用、Workflow执行和监控；
- 数字员工关联能力并承接任务；
- 任务调度、Worker执行、失败重试和恢复；
- 运营指标统计、数据分析和报告生成。

后续场景在相应模块完成开发后纳入端到端测试，不作为首期M2/M3交付的前置阻塞项。

## 十二、用户验收测试（UAT）

### 12.1 参与角色

根据实际业务安排角色，不在本文件中虚构具体人员：

- 系统管理员；
- 组织或部门管理员；
- 招聘/人才选拔人员；
- 人才档案管理人员；
- 测评/面试人员；
- 业务管理人员；
- 候选人（涉及候选人门户时）。

### 12.2 UAT执行方式

1. 确认验收版本和范围；
2. 准备验收环境、账号和数据；
3. 向参与人员说明场景和验收标准；
4. 按角色执行场景；
5. 记录实际结果和证据；
6. 登记缺陷和业务改进意见；
7. 修复后执行复测；
8. 形成通过、有条件通过或不通过结论；
9. 由授权验收责任人确认。

### 12.3 验收结论

- **通过：** 所有阻断性标准满足，无未解决的严重缺陷。
- **有条件通过：** 核心业务可用，遗留问题有风险评估、责任人、绕行方案和计划完成版本，并经授权方接受。
- **不通过：** 核心流程无法完成、存在严重安全/数据问题或关键验收标准未满足。

## 十三、缺陷管理与回归测试

### 13.1 缺陷等级

| 等级 | 定义 | 处理原则 |
|---|---|---|
| S1 致命 | 数据泄露、严重越权、数据损坏、核心服务整体不可用 | 阻断发布，优先处理 |
| S2 严重 | 核心业务流程中断、关键结果错误且无可接受绕行方案 | 阻断相关里程碑或发布 |
| S3 一般 | 非核心功能异常、存在可接受绕行方案 | 评估后安排修复 |
| S4 轻微 | 文案、布局或低影响体验问题 | 纳入迭代计划 |

缺陷等级最终由业务影响、安全影响、数据影响和复现范围综合判断。

### 13.2 缺陷记录字段

- 缺陷编号；
- 标题和所属模块；
- 发现版本、环境和时间；
- 严重等级和优先级；
- 复现步骤；
- 输入数据和预期结果；
- 实际结果和证据；
- 关联任务、接口和用例；
- 责任人和处理状态；
- 修复版本；
- 回归结果；
- 是否引入其他风险。

### 13.3 缺陷状态

`新建 → 已确认 → 修复中 → 待回归 → 回归通过 → 已关闭`

其他状态：`拒绝/重复/无法复现/延期`，均须填写原因。

### 13.4 回归策略

- 缺陷修复后先执行原失败用例；
- 再执行受影响模块的定向回归；
- 涉及公共组件、权限、数据模型、API契约和任务基础设施时扩大回归范围；
- 里程碑验收前执行核心业务端到端回归；
- 发布候选版本执行完整发布回归清单。

- 异步任务的失败和恢复路径经过验证；
