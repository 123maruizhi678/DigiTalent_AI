# 接口设计 · 2026 AI 数字化人才平台

> 配套：PRD + 概要设计 + 详细设计。所有接口基址前缀 `/api`（见 `backend/app/main.py`）。
> 说明：标注「✅实测」的接口取自实际路由代码（`resumes.py`、`agent_management.py` 等）；未读取实现细节的模块按路由前缀 + REST 约定推导，以 FastAPI 自动生成的 OpenAPI 文档（`/docs`）为最终准。

---

## 1. 接口规范

- 风格：RESTful，JSON 请求/响应；FastAPI `async def` 异步。
- 基址：`/api`；版本内置于路径（当前无独立 /v1，路由直接挂在 /api 下）。
- 鉴权：用户会话/令牌（具体方案见 `user-center` + `sys_role_permissions`）；行/字段级权限随角色 `data_scope` 注入查询。
- 分页：查询类列表接口统一 `page`（默认1）、`page_size`（默认20，上限200）Query 参数，返回 `{items, total, page, page_size}`。
- 限流/熔断：需求强制；当前仅 Celery 队列级限流，接口级限流待补（PRD 决策项 4）。
- 实时：部分长任务用后台任务 + 轮询（如 `/resumes/queue`）；SSE 实时推送端点待确认。

---

## 2. 统一返回格式

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

- `code`：业务码，`0` 成功，非 0 为错误（见错误码表）。
- `message`：可读提示。
- `data`：业务载荷；列表接口为 `{items:[...], total, page, page_size}`。
- 失败示例：`{ "code": 400, "message": "简历文件为空", "data": null }`

---

## 3. 错误码表

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 400 | 400 | 参数错误 / 业务校验失败 |
| 401 | 401 | 未认证 / 令牌失效 |
| 403 | 403 | 无权限（角色/数据范围） |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 冲突（唯一键重复等） |
| 422 | 422 | Pydantic 校验失败 |
| 429 | 429 | 限流触发（待接入） |
| 500 | 500 | 服务内部错误 |
| 503 | 503 | 依赖不可用（AI/向量库/存储） |

全局异常由 `app/exceptions/custom_exception.py` 归一化；AI 调用异常附 `raw_error` 便于排查。
