## 1. 验收原则

1. 按业务功能、端到端流程、权限安全、数据正确性、非功能要求分别验收。
2. 每项验收均应具备测试前置条件、操作步骤、预期结果和实际结果。
3. 关键业务链路必须验证成功路径、失败路径和权限不足路径。
4. AI 生成结果应同时验证结果内容、依据或过程记录及人工确认机制。
5. 未纳入本期范围的功能不作为本期验收失败项。
6. 需求未明确的量化指标，应先确定测试口径再开展正式验收。

## 2. 功能验收标准

| 编号 | 模块 | 验收内容 | 通过标准 |
|---|---|---|---|
| F-01 | 项目管理 | 项目群、项目、项目人才需求 | 项目可独立存在或归属项目群；项目下可有多个项目需求，需求可关联多个岗位并共享部分岗位条件 |
| F-02 | 岗位管理 | 岗位字典、岗位条件 | 能维护岗位及其筛选条件，并供人才匹配流程使用 |
| F-03 | 简历管理 | 简历上传及文件管理 | 上传成功后形成业务记录，原文件可定位；单次批量上传不超过 20 份；同一人才可保留多份简历及历史版本 |
| F-04 | 简历解析 | 解析任务及结构化结果 | 能发起解析、查看状态、保存待确认结构化结果；失败自动重试，达到上限后标记失败并允许人工重发 |
| F-05 | 人才匹配 | 条件过滤、评分及原因 | 能输出匹配结果、评分和原因，结果关联岗位与人才 |
| F-06 | 招聘管理 | 候选人管理及 JD | AI 生成内容为草稿，HR 确认后才能发布 |
| F-07 | 邀请管理 | 候选人邀请有效期 | 显示具体失效日期和时间；发起人及候选人均可收到有效期提示；过期后提示重新邀请 |
| F-08 | 人才档案 | 统一人才主档案 | 候选人与员工关联统一主档案，并保留各自身份信息 |
| F-09 | 人才画像 | AI 生成及人工维护 | AI 生成画像草稿，HR 确认后生效；保留所有历史版本、来源和变更记录 |
| F-10 | 测评管理 | 题库、试题、试卷 | 能完成题目维护、分类、组卷及试卷管理 |
| F-11 | 在线测评 | 答题及提交 | 授权用户能够参加测评并提交答卷，答卷可追踪 |
| F-12 | 评分管理 | 客观题及主观题评分 | AI 对主观题评分，考官可复核和调整；评分及复核结果关联答卷、人才及测评 |
| F-13 | 面试管理 | 邀约及多轮面试 | 能记录面试邀约、各轮过程和结论 |
| F-14 | Agent 管理 | 注册、状态、能力及运行记录 | 能维护 Agent 信息并查询运行状态和执行记录 |
| F-15 | Workflow | 固定主流程与动态分支 | 工作流能够按定义执行，动态分支按条件进入对应节点；中断后支持从失败节点恢复或由授权人员重新执行 |
| F-16 | 工具权限 | Agent 工具调用授权 | 无授权或超出授权范围的工具调用被拒绝并记录 |
| F-17 | 数字员工 | 创建、职责及关联 | 平台管理员可创建和授权；数字员工管理员可按授权管理日常职责及任务 |
| F-18 | 任务调度 | 定时、周期、手动触发 | 支持定时、周期和手动触发；执行状态、结果、重试和异常可查询 |
| F-19 | 智能问数 | 自然语言转 SQL | 能生成只读查询 SQL，平台完成权限及安全校验后再执行；禁止通过 NL2SQL 写入、修改或删除数据 |
| F-20 | 数据分析 | 统计、图表及报告 | 查询结果与授权数据一致，图表和报告能够展示结果 |
| F-21 | 组织管理 | 用户、部门及角色 | 能维护组织、用户、角色及分配关系；一个用户可拥有多个系统角色，但一个账号同一时点只能对应一种业务身份 |
| F-22 | 权限管理 | 菜单、操作和数据范围 | 权限配置生效，未授权访问被拒绝 |
| F-23 | 审计管理 | 关键操作记录 | 能查询操作人、时间、对象、操作类型及结果 |

## 3. 端到端业务流程验收

### 3.1 人才需求到候选人匹配

**前置条件：** 已创建项目群、项目、人才需求及岗位条件；准备可用测试简历。

**步骤：**
1. 创建项目群及项目。
2. 创建项目人才需求。
3. 配置岗位条件。
4. 上传一份或多份简历。
5. 发起简历解析。
6. 查看结构化解析结果。
7. 执行人才匹配。
8. 查看匹配评分、原因及名单。

**通过标准：**
- 业务对象关系正确。
- 简历文件和解析结果均可追踪。
- 匹配结果关联正确的人才、岗位及项目。
- 解析或匹配失败时有明确状态和异常记录。

### 3.2 候选人邀请及参与流程

**步骤：**
1. 有权限的招聘人员发起候选人邀请。
2. 查看邀请有效期。
3. 候选人收到邀请并登录。
4. 候选人访问本人授权的招聘、测评或面试入口。
5. 使用过期邀请进行访问。

**通过标准：**
- 邀请记录包含发起人、候选人、邀请时间和失效时间。
- 发起人及候选人均能看到具体失效日期和时间提示。
- 有效邀请可按权限使用。
- 过期邀请不能继续用于开通或登录授权，并提示重新邀请。
- 候选人不能访问内部管理页面及其他候选人数据。

### 3.3 人才档案与画像流程

**步骤：**
1. 创建或导入人才业务资料。
2. 建立统一人才主档案。
3. 关联候选人或员工身份。
4. 触发 AI 画像生成。
5. 查看画像、标签、优势及待提升项。
6. 人工调整画像。

**通过标准：**
- 人才主档案及身份关联正确。
- 画像结果能够关联人才档案。
- 人工调整后结果正确保存，并保留必要变更信息。

### 3.4 测评与面试流程

**步骤：**
1. 创建题库及试题。
2. 创建试卷。
3. 授权用户参与测评。
4. 提交答卷。
5. 执行评分。
6. 查看测评结果。
7. 创建面试邀约并记录多轮面试结论。

**通过标准：**
- 题目、试卷、答卷及评分关系正确。
- 测评结果能够关联人才档案。
- 面试邀约和多轮面试记录完整。
- 测评与面试按配置流程执行。
- 不要求实现错题复习计划。

### 3.5 Agent、Workflow 与数字员工流程

**步骤：**
1. 注册并配置 Agent。
2. 定义 Workflow 主流程和动态分支。
3. 创建数字员工并配置职责。
4. 将多个 Agent 或 Workflow 关联到数字员工。
5. 配置任务触发方式。
6. 触发任务并查看执行过程。
7. 使用无权限工具或超范围参数进行调用。

**通过标准：**
- Agent、Workflow、数字员工及任务关联正确。
- 工作流主流程及动态分支执行正确。
- 任务执行状态、结果和异常可追踪。
- Agent 继承所属任务或数字员工的授权上下文。
- 无权限工具调用被拒绝并产生审计记录。

### 3.6 智能问数流程

**步骤：**
1. 使用不同角色登录。
2. 分别提出相同或不同的业务数据问题。
3. 查看生成的 SQL 或查询过程记录。
4. 检查平台权限及安全校验。
5. 查看查询结果。
6. 尝试访问超出数据范围的数据。

**通过标准：**
- 查询仅访问当前用户有权访问的数据。
- SQL 经平台校验后才执行。
- 不允许通过自然语言请求绕过权限限制。
- 越权查询被拒绝并记录。

## 4. 权限与安全验收

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| S-01 | 未登录访问受保护接口 | 拒绝访问 |
| S-02 | 用户访问无权限菜单或接口 | 拒绝访问 |
| S-03 | 部门用户查询其他部门数据 | 默认拒绝 |
| S-04 | 用户访问未授权项目 | 拒绝访问 |
| S-05 | 已获项目授权的跨部门用户访问项目 | 仅能访问授权项目及范围内数据 |
| S-06 | 候选人访问内部管理功能 | 拒绝访问 |
| S-07 | 候选人访问其他候选人数据 | 拒绝访问 |
| S-08 | Agent 调用未授权工具 | 拒绝执行并记录 |
| S-09 | Agent 尝试扩大继承权限 | 拒绝执行并记录 |
| S-10 | 数字员工管理员尝试修改平台整体授权 | 不允许自行扩大权限 |
| S-11 | 用户执行敏感操作 | 按配置触发分级审批或二次确认 |
| S-12 | 用户执行关键数据导出或删除 | 校验独立权限并保留审计记录 |
| S-13 | 候选人使用过期邀请 | 拒绝使用并提示重新邀请 |

## 6. 非功能验收

### 6.1 性能目标与规模基线

本期已确认的规模和处理约束：

| 指标 | 确认目标 | 验收方式 |
|---|---:|---|
| 初期注册用户 | ≤100 人 | 以测试账号及用户记录核对 |
| 同时在线用户 | ≤20 人 | 并发登录及典型业务操作测试 |
| 单次批量简历上传 | ≤20 份 | 上传边界测试，验证 20 份可处理、超过上限时有明确提示 |
| Agent 单次任务执行时间 | ≤2 分钟 | 构造正常、超时及异常任务，检查超时处理 |
| 数据备份 | 每天一次 | 检查备份任务记录，并定期执行恢复验证 |

原设计文件提出的下列指标保留为待制定测试口径的设计目标，不代表已经完成性能验收：

| 指标 | 原设计目标 | 验收说明 |
|---|---:|---|
| 页面响应时间 | ≤ 1 秒 | 明确页面范围及统计方式后测试 |
| 普通接口响应时间 | ≤ 1 秒 | 明确接口范围、并发量及统计口径后测试 |
| 向量检索耗时 | ≤ 500 毫秒 | 明确数据规模及检索参数后测试 |
| 报表生成时间 | 3–5 秒 | 明确报表复杂度及数据量后测试 |
| 向量检索召回率 | ≥ 95% | 需要准备标注测试集并明确计算方式 |
| 热点缓存命中率 | ≥ 98% | 原设计依赖缓存层；当前暂不使用 Redis，因此该项不能直接作为本期 Redis 验收项 |

以上指标不能仅凭单次演示判定通过。正式验收前需确认测试环境、数据量、并发量、采样次数及统计方式。

### 6.2 可用性与可维护性

- 服务异常能够被识别并记录。
- 长时间运行任务支持后台执行及状态查询。
- 业务服务与模型、文件存储及向量服务保持适当解耦。
- 关键业务操作、AI 调用和任务执行具备必要日志。
- 重要数据具备已验证的备份和恢复方案。

本期不设固定可用性百分比。验收重点为核心服务监控、异常告警、故障定位和恢复机制可用，并提供必要的运行记录。

### 6.3 安全与合规

- 密码、模型密钥和敏感配置得到保护。
- 个人信息访问及导出受权限控制。
- 重要操作有审计记录。
- 测试数据按要求脱敏。
- 备份与恢复流程可验证。
- 数据保留及删除规则能够执行。

具体安全等级、加密算法、法规适用范围及合规测试方法需另行确认。

## 7. 测试数据要求

- 使用虚构或经过脱敏的候选人简历和个人资料。
- 准备覆盖不同岗位条件的简历样本，包括满足、不满足及部分满足条件的样本。
- 准备不同部门、不同角色及不同项目授权的测试账号。
- 准备有效、临近失效和已过期的候选人邀请记录。
- 准备客观题、主观题及不同评分结果的测评样本。
- 准备成功、失败、超时及权限不足的 Agent / Workflow 任务样本。
- 准备能够验证数据范围隔离的智能问数样本。

## 8. 验收交付物

1. 功能测试用例及执行结果。
2. 端到端业务流程测试记录。
3. 权限与安全测试记录。
4. 数据正确性及跨存储关联检查记录。
5. 性能测试报告。
6. 缺陷清单及修复复测记录。
7. 部署、配置及运行说明。
8. 数据库结构、接口文档及必要的业务流程说明。

## 9. 验收结论规则

- **通过：** 本期范围内的必验功能和关键流程均达到对应通过标准；不存在阻断核心业务或造成越权访问的严重问题。
- **有条件通过：** 核心流程可用，但存在已登记、已明确责任人和修复期限的非阻断问题，并经项目相关方书面认可。
- **不通过：** 核心业务流程无法完成、关键数据错误、权限隔离失效，或存在未解决的严重安全问题。

最终验收负责人、验收日期、性能测试口径、缺陷等级划分及签字流程，由项目相关方确定。

## 11. 本轮需求补充验收项

### 11.1 业务对象与状态规则

1. 项目允许独立存在，也允许归属于项目群；项目需求可关联多个岗位。
2. 项目关闭后历史数据保留，管理员能够重新开启。
3. 人才疑似重复记录由系统识别，HR 确认后才能合并。
4. 候选人淘汰后，HR 可填写原因重新激活，并保留状态变更记录。
5. 候选人录用后，账号业务身份转换为员工，保留原人才主档案及候选人阶段记录。
6. 项目、候选人、简历解析、Agent 任务及 Workflow 的状态变化、失败、重试、恢复和取消均可追踪。

### 11.2 AI 质量与人工确认

1. 简历解析结果先保存为待确认结果，HR 确认后才能写入正式人才档案。
2. 人才岗位匹配必须展示评分和匹配原因，最终筛选由 HR 决定。
3. 人才画像必须先生成草稿，HR 确认后才能成为正式画像；历史版本可追溯。
4. 主观题 AI 评分允许考官复核和调整，记录原始评分及最终评分。
5. AI 生成 JD 后仅为草稿，HR 确认后才能发布。
6. Agent 普通授权操作可执行；敏感操作按风险等级进入人工确认或审批。
7. NL2SQL 仅允许只读查询，必须经过权限校验和 SQL 安全检查。

### 11.3 数据生命周期

1. 同一人才可关联多份简历，能够区分来源、用途、有效状态并查看历史版本。
2. 人才画像保留所有历史版本。
3. 人才档案逻辑删除后，关联数据进入待清理状态；清理前完成关联校验，清理结果可追踪。
4. 候选人个人信息删除请求经管理员审核后，按数据类别删除或匿名化，并处理各存储关联数据。
5. 日志按类型设置独立访问权限和保留期限。
6. 数据每天备份一次，并定期验证恢复能力。

### 11.4 权限与组织变更

1. 一个用户可拥有多个系统角色，权限按授权合并，但不得突破数据范围和禁止规则。
2. 一个账号同一时点只能对应一种业务身份。
3. 用户停用后无法登录，相关权限撤销，历史业务数据保留。
4. 员工调部门后，原部门数据权限撤销，按新部门重新授权。
5. 跨部门项目授权由平台管理员审批，且具备授权期限。
6. 权限撤销后，运行中的 Agent 任务必须重新校验授权；未授权操作被阻断，任务按风险暂停或终止。
7. 敏感操作按业务类型和风险配置审批人及审批层级。
