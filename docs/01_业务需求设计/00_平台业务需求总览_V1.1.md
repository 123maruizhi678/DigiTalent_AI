## 1. 项目定位与目标

### 1.1 项目定位

2026 AI 数字化人才平台是一个以人工智能技术为核心的人才数字化管理与业务协作平台。

平台围绕人才选拔、人才档案与人才画像、智能测评与面试等人才业务，结合 AI Agent、多智能体协作、工作流编排、数字员工、任务调度及自然语言数据分析能力，形成统一的人才业务管理与智能协作平台。

平台采用前后端分离架构，通过 AI 中台统一管理智能体、工作流和模型供应商，为不同人才业务场景提供智能化支持。

### 1.2 建设目标

1. 建立统一的人才选拔管理能力，支持项目人才需求、岗位条件、简历解析、人才筛选及岗位匹配。
2. 建立人才档案与人才画像能力，集中管理人才基础信息、能力、优势、待提升项及标签。
3. 建立智能测评与面试管理能力，支持题库、试题、试卷、在线测评、评分及面试过程管理。
4. 建立 AI Agent 与工作流管理能力，实现智能体注册、运行、发布、协作及工作流编排。
5. 建立数字员工与任务调度能力，支持数字员工注册、职责管理、职责流程及任务调度。
6. 提供自然语言数据分析能力，辅助管理人员进行人才数据分析、人才缺口分析和业务决策。
7. 建立统一的用户、组织、角色、权限和操作审计体系。

### 1.3 建设范围

本项目当前保留以下七个业务领域：

- 人才选拔
- 人才档案与人才画像
- 智能测评与面试
- AI Agent 与工作流管理
- 数字员工与任务调度
- 数据智能与运营决策
- 用户、组织与权限管理

以下两个业务领域暂不纳入当前项目需求范围：

- 岗前培养与培训课程
- 企业知识库

## 2. 目标用户与使用场景

### 2.1 目标用户

根据现有设计中的用例角色，平台涉及以下用户：

| 用户角色 | 主要职责 | 使用场景 |
|---|---|---|
| 员工 | 使用个人档案及平台授权功能 | 查看个人档案、参与在线测评、参与面试 |
| HR / 招聘人员 | 负责人才选拔及招聘业务 | 简历筛选、岗位条件配置、候选人管理、面试管理 |
| 管理员 / 运维人员 | 负责平台配置和运行管理 | 用户管理、模型配置、Agent 管理、数字员工管理、任务调度、日志审计 |
| 管理层 | 查看人才数据和业务运营情况 | 智能问数、人才缺口分析、决策建议、运营审计 |
| 候选人 | 参与招聘及考核流程 | 面试、答题、提交测评 |
| 业务管理人员 | 负责相关人才业务及测评管理 | 题库维护、试卷管理、测评结果查看、业务数据管理 |

> 业务管理人员是否作为独立角色设置，待确认。员工与候选人是否使用同一套账号体系，待确认。

### 2.2 主要使用场景

**场景一：人才招聘与筛选**

HR 根据项目人才需求配置岗位条件，上传候选人简历，系统进行简历解析和岗位匹配，输出满足及不满足条件的名单。

**场景二：人才档案管理**

系统根据候选人及员工的业务资料形成结构化档案，进一步形成能力画像、优势、待提升项和人才标签。

**场景三：智能测评与面试**

管理人员维护题库并创建试卷，候选人或员工参与测评，系统完成评分和结果记录；招聘人员管理面试邀约及多轮面试过程。

**场景四：智能业务协作**

通过 Agent 和工作流将不同业务任务组织起来，根据任务类型调用相应智能体，并记录执行状态和结果。

**场景五：数字员工与任务调度**

管理员配置数字员工及其职责流程，根据定时、周期或手动触发规则执行相关任务。

**场景六：数据分析与决策**

管理层通过自然语言查询业务数据，获取统计结果、图表和分析报告，辅助人才及业务决策。

**场景七：平台组织与权限管理**

管理员维护用户、部门、角色及功能权限，控制不同用户能够访问的功能和业务数据范围。

### 2.3 待确认事项

- 员工与候选人是否使用同一套账号体系。
- 外部候选人是否直接登录平台。
- 不同角色是否存在跨部门协作权限。
- 是否存在独立的数字员工管理角色。
- 业务管理人员是否作为独立角色设置。
- 各角色是否需要独立门户或独立操作界面。

### 3.2 统一术语说明

- **项目需求（Project Demand）：** 企业针对某个项目提出的人才数量、岗位及到岗时间等需求。
- **岗位条件（Job Profile）：** 用于描述岗位要求、筛选条件和评分规则的配置。
- **简历解析（Resume Extraction）：** 从原始简历中提取个人信息、教育经历、技能及工作经验等结构化内容。
- **人才匹配（Job Matching）：** 根据岗位条件，对候选人进行条件过滤和综合评分。
- **人才画像（Talent Profile）：** 对个人能力、优势、待提升项和标签进行综合描述。
- **Agent：** 面向具体任务的智能体。
- **Workflow：** 多个任务或智能体按照预设流程执行的工作流。
- **数字员工（Digital Worker）：** 平台中承担特定数字化业务职责的虚拟执行主体。
- **NL2SQL：** 将自然语言问题转换为数据库查询语句的技术能力。

## 5. 主要业务流程

### 5.1 人才选拔流程

项目人才需求 → 岗位条件配置 → 简历上传 → 简历解析 → 人才匹配 → 匹配结果生成 → 候选人名单管理 → JD 发布及邀约 → 面试管理 → 测评与考核 → 录用。

### 5.2 简历解析与人才匹配流程

1. HR 上传一份或多份简历。
2. 系统保存原始文件。
3. 创建简历记录和解析任务。
4. 调度器认领待处理任务。
5. 简历解析 Agent 调用解析能力。
6. 提取候选人结构化信息。
7. 保存解析结果。
8. 生成或更新人才向量。
9. 调用岗位匹配 Agent。
10. 执行硬性条件过滤及综合评分。
11. 保存匹配结果。
12. 输出满足及不满足条件的名单。

### 5.3 人才画像流程

人才档案及业务数据 → 人才信息整理 → 能力维度分析 → 人才标签关联 → 优势与不足分析 → 形成画像 → 人才档案更新。

具体触发条件及画像更新策略：待确认。

### 5.4 测评与面试流程

题库维护 → 试题管理 → 创建试卷 → 用户参与测评 → 提交答卷 → 自动评分及智能评分 → 生成测评结果 → 面试邀约及多轮面试 → 记录面试结论。

测评与面试的先后关系、是否互为必经环节：待确认。

### 5.5 多智能体工作流流程

任务触发 → LangGraph 工作流启动 → 任务状态初始化 → 判断执行分支 → 调用对应 Agent → 接收执行结果 → 状态更新 → 判断是否继续执行 → 工作流完成 → 保存执行记录。

具体 Agent 的协作关系、调用顺序及人工介入条件：待确认。

### 5.6 数字员工任务执行流程

数字员工注册 → 配置数字员工职责 → 定义职责流程 → 配置任务触发规则 → 触发任务 → 调用关联 Agent 或业务能力 → 执行任务 → 记录执行结果及状态。

具体数字员工的职责类型、触发条件、执行权限及失败处理方式：待确认。

### 5.7 智能问数流程

用户输入自然语言问题 → 识别查询意图 → 获取允许访问的数据范围 → 转换为查询语句 → 执行数据查询 → 生成统计结果 → 图表展示及分析报告。

具体 SQL 安全校验及查询审批机制：待确认。

### 5.8 用户与权限管理流程

用户及部门信息维护 → 角色配置 → 分配用户角色 → 配置菜单及操作权限 → 配置数据范围 → 用户访问业务功能 → 系统执行权限校验 → 记录重要操作。

具体用户开通、停用、角色变更及权限审批流程：待确认。

### 7.5 数据流转关系

**简历与人才数据：**

简历原文件 → MinIO → 简历解析 → 结构化结果写入 MySQL → 人才向量写入 Milvus → 人才匹配 → 匹配结果写入 MySQL。

**人才关系数据：**

人才、技能及岗位信息 → 关系整理 → 按设计写入 Neo4j → 为人才画像及人才关系分析提供数据支持。

**测评与面试数据：**

题库及试题 → 试卷 → 答卷 → 评分 → 测评结果及错题记录写入 MySQL；面试邀约及多轮面试结果关联候选人记录。

**Agent 与数字员工数据：**

Agent 注册及配置 → 工作流定义 → 任务调度触发 → Agent 或数字员工执行 → 执行状态及日志写入 MySQL。

**业务查询数据：**

用户请求 → 权限校验 → 业务服务 → MySQL / Milvus / Neo4j 等数据源 → 结果整理 → 返回用户。

### 7.6 数据管理要求

1. 结构化业务数据由 MySQL 统一管理。
2. 向量数据由 Milvus 管理，并保留与业务数据的关联关系。
3. 原始简历及业务附件由 MinIO 管理。
4. 图谱关系由 Neo4j 管理。
5. 不同存储之间应保留必要的数据关联标识。
6. 数据更新、删除和同步机制应保持一致性。

数据保留周期、备份策略、数据脱敏、数据删除及跨库一致性策略：待确认。
