## 6. 关键流详细用例

### 6.1 简历解析 → 匹配（TC-RES-01 / TC-MAT-02）

- **前置**：`seed_data.sql` 已加载；`job_profiles` 含"高级算法工程师"条件（id=3）；MinIO 有样例 PDF。
- **步骤**：
  1. `POST /api/resumes/batch`（multipart，含 `job_profile_id=3`），预期 `code=0` 且 `accepted=N`。
  2. `POST /api/resumes/parse-next` 认领并解析；`GET /api/resumes/queue` 预期该任务 `completed`。
  3. `GET /api/resumes/match-lists?job_profile_id=3&passed=true` 取名单。
  4. 取首条 `match_lists.reason` 与 `total_score`。
- **预期**：解析出的 `parsed_resumes` 字段与样例一致（见 `data/resume_parse_eval.json`）；匹配分 ∈[0,100]，通过线 `passing_threshold=70`；`reason` 非空且可解释。
- **数据**：`data/resume_parse_eval.json`、`data/match_eval.json`。

### 6.2 RAG 知识库问答（TC-RAG-02）

- **前置**：`business_knowledge` + `knowledge_chunks` 已向量化入 Milvus（id=1..N）。
- **步骤**：`POST /api/knowledge-base/ask` `{"question":"年假天数如何计算？","category_id":1}`。
- **预期**：`code=0`；`data.answer` 非空；`data.sources` 含可追溯 `knowledge_chunks` 来源；答案与标注一致（见 `data/rag_eval.json`），准确率≥95%。
- **护栏**：诱导性/越权问题应触发 `ai_safety` 拦截或无据拒答。

### 6.3 测评提交评分（TC-EXM-03）

- **前置**：`exams`(id=1, `pass_score=60`)、`questions` 已建。
- **步骤**：`POST /api/exams/1/submit` `{"answers":[{"question_id":1,"answer":"..."}]}`。
- **预期**：`exam_submissions.score` 计算正确，`result=passed/failed` 按 `pass_score`；`wrong_questions` 自动生成错题；`review_plans` 可生成。

### 6.4 数据决策问数（TC-DEC-01 / ⚠️）

- **前置**：`data-decision` 模块可用（NL2SQL 引擎归属待确认，PRD 决策项 2）。
- **步骤**：`POST /api/data-decision/ask` `{"question":"本月各岗位通过率是多少？"}`。
- **预期**：返回数据表 + 图表 + 文字解读；结果随提问者角色做行/字段级过滤（TC-DEC-02）。
- **⚠️**：若 Vanna.ai 未回填且自研引擎未就绪，本用例挂起并登记缺陷。

## 9. 非功能 / 性能 / 安全用例要点

- **TC-PER-01～03**：用压测脚本对 `resumes/match-lists`、`knowledge-base/ask`、向量检索施压；断言时延与并发。PgSQL 分析库缺失时，大数据报表用例标注"待引入后补测"。
- **TC-SEC-01（限流）⚠️**：当前仅 Celery 队列级限流，接口级 429 未确认 → 先确认实现（PRD 决策项 4），否则挂起。
- **TC-SYS-03（行级）**：以"业务负责人"身份请求他人部门数据 → 期望 403 / 空结果（依赖 `data_scope` 注入，需逐接口复核）。
- **TC-SYS-04（字段级）**：HR 查候选人列表，薪资等敏感字段按角色脱敏；管理层可见。
- **TC-SEC-02**：传输/存储加密、敏感字段脱敏、备份容灾专项检查。
