## 3. 四类业务对象关系
Agent 提供能力；Workflow 管理节点、连接、顺序、分支配置与模拟执行记录；数字员工拥有角色、职责和能力配置，可调用 Agent 或参与 Workflow；任务为具体工作。员工表展示角色与统一 Agent 能力，任务表展示名称、类型、来源、执行对象、状态、时间、结果和异常信息。现有通用编辑区只登记本地配置，不构成真实执行引擎。

## 4. Workflow 画布调整结果
基于现有 Vue、Pinia、Element Plus，未安装依赖。支持开始、结束、Agent、工具、条件判断、人工审核六类节点；支持选中、信息查看、参数编辑、增删及删除关联连线、基本信息配置、连线增删及条件配置、保存快照、模拟执行状态与结果。
保存和模拟前检查名称、起终点、断连、重复边、自连、环路和无后续步骤。模拟按拓扑顺序展示执行中、完成及最终说明，不调用服务、不求值分支、不进行真实人工审批。采用列表式画布与连线配置区，未实现自由拖拽和图形连线。保存限当前 Pinia 会话，刷新重置。

## 6. 系统技术状态与服务监控
替换旧快照页面及菜单名称。config/technology.ts 集中维护八类技术、七种状态语义、服务清单和待办。服务表包含名称、地址、状态、部署方式、版本、最近检查时间。Milvus 为待部署 / Docker Run，MinerU 为 Conda + pip；Redis、Docker Compose 暂不采用，未将 Celery 当作已用组件。技术确认不等于已安装或已启动，不伪造真实版本与检查时间。移除旧技术页未确认组件和虚构性能结论；简历解析链路同步清理 OpenCV、PyPDF 及运行中状态。

## 7. 演示数据标识
全局使用“当前展示为原型演示数据，尚未连接真实业务数据。”统一说明统计卡片、表格、图表与 AI 输出为示例；DemoTable 和 BusinessChart 增加局部说明，智能问数输出标记模拟结果。服务状态另标为未连接 / 未检测。

## 8. 人才数据证据追溯
四类页面均增加证据查看抽屉，数据集中管理于 config/evidence.ts。使用明确标识的独立 DEMO-C001 样例，不冒充其他候选人的证据。
- 简历：原始信息摘要、结构化字段、技能、工作经历、项目经历、解析异常、可切换人工复核状态。
- 匹配：岗位要求、对应经历、匹配依据、不匹配或待验证原因、分项得分，独立样例总分 81/100。
- 画像：模拟问答及引用定位，覆盖简历、项目、工作、标签、测评、面试六种来源。
- 测评面试：题组来源、评分规则、面试评价记录与能力判断依据。
提供记录标识、版本、页码和摘录，移除联系方式、住址、证件等敏感信息。没有真实文件检索、RAG 或推理。尚未为所有旧候选人逐一关联证据，独立样例与旧卡片分数不属于同一评价记录。

## 9. 登录与权限设计
登录页明确管理员创建或邀请、不开放自主注册。保留用户与角色布局、组织管理、权限配置和审计样例。业务路由标记 requiresAuth，守卫保护演示导航；Store 将 demoSession 与 authenticated 分离，演示进入不会设为真实认证成功，退出清理会话及权限。
api/auth.ts 预留登录、会话、授权、退出和邀请接口，不发请求；具体路径和契约待后端设计确认。前端菜单与守卫不能代替逐请求后端授权、数据范围控制和安全审计。当前审计表为样例。
