# P6-IAM-002：角色与权限数据模型整体实施流程

-   **所属阶段：** 第六阶段：系统开发与模块实现
-   **所属里程碑：** M1：基础平台与公共业务能力建设
-   **任务编号：** P6-IAM-002
-   **任务名称：** 角色与权限数据模型
-   **交付目录：** `docs/06_开发与测试管理/开发记录/1105/M1/P6-IAM-002/`
-   **流程版本：** V1.0

> 本文件定义任务实施流程，不替代已批准的业务、权限及数据库设计。角色类型、权限类型、用户角色分配规则、数据权限范围、字段及约束，必须从已批准的正式设计文件中提取，不得自行补充或改变。

## 一、任务目标

在 P6-IAM-001
用户与组织数据模型的基础上，按照已批准的业务与安全权限设计，完成角色、权限及其关联关系的数据模型建设，为后续邀请制账号、登录认证、后端授权和权限审计提供数据基础。

主要交付：

1.  经核对的角色与权限数据模型设计。
2.  SQLAlchemy ORM 模型及模型注册。
3.  人工维护的 MySQL 建表 SQL。
4.  ORM 与 SQL 一致性核对结果。
5.  开发记录、检查记录和验收报告。

## 二、任务范围与边界

### 2.1 本任务范围

-   角色数据模型。
-   权限数据模型。
-   用户与角色关联模型。
-   角色与权限关联模型。
-   已批准设计明确要求的数据权限相关模型或字段。
-   对应 ORM 实现及模型注册。
-   对应人工 MySQL SQL。
-   模型、SQL 与批准设计的一致性检查。

### 2.2 不在本任务内提前实现的内容

-   P6-IAM-003：邀请制账号创建流程。
-   P6-IAM-004：登录、JWT 与当前用户接口。
-   P6-IAM-005：后端认证授权依赖及接口授权执行。
-   P6-IAM-006：权限变更与审计接入。

如模型实现依赖上述任务中的约定，应记录依赖和待确认事项，不擅自提前实现完整业务流程。

## 四、各阶段工作内容

### 阶段 0：任务启动与资料核对

**目标：** 确认任务依据、现有实现基础和任务状态。

**工作内容：**

1.  调用项目级 `digitaltalent-development-workflow` Skill。
2.  按用户明确授权读取 P6-IAM-002 所需正式设计文件和任务管理记录。
3.  核对 P6-IAM-001 已完成的用户、组织 ORM 模型及相关 MySQL SQL。
4.  核对公共 Base、Mixin、模型注册方式和数据库字段规范。
5.  确认 P6-IAM-002 的任务状态、前置依赖和交付目录。

**阶段交付：** 资料依据清单、现状核对结果。

**门禁：**
设计文件或关键依赖缺失时，先报告缺失项，不扩大文档访问范围，不根据猜测继续设计。

### 阶段一：已批准设计核对

**目标：** 从正式设计中提取 P6-IAM-002 的明确要求。

**核对内容：**

1.  角色定义、角色编码及角色状态规则。
2.  权限类型、权限标识及资源归属规则。
3.  用户与角色的关联基数及分配规则。
4.  角色与权限的关联规则。
5.  数据权限范围及其适用对象。
6.  逻辑删除、唯一性及关联有效性规则。
7.  字段、索引、外键、CHECK 等数据库约束要求。
8.  与 P6-IAM-001 用户、组织模型的关系。
9.  与 P6-IAM-003～006 的职责边界。

**阶段交付：** `01_P6-IAM-002角色与权限数据模型设计核对报告.md`

**门禁：**
正式设计之间出现冲突、关键规则缺失或无法确定时，列出原文依据和待确认问题，暂停相关设计，不自行裁定。

### 阶段二：角色与权限数据模型梳理

**目标：** 将批准的业务规则整理为可实现的数据模型方案。

**工作内容：**

1.  列出本任务需要新增或复用的实体。
2.  明确实体之间的关联关系和基数。
3.  整理各实体字段及字段来源。
4.  整理主键、外键、唯一性和普通索引要求。
5.  整理状态、逻辑删除及关联有效性规则。
6.  明确数据权限相关结构是否属于本任务；仅实现正式设计明确要求的部分。
7.  检查是否与现有用户、组织模型重复或冲突。

**阶段交付：** 数据模型清单、实体关系说明、字段与约束映射表。

**门禁：**
模型必须能够逐项追溯到已批准设计；无依据的新增字段、权限类型或规则不得进入实现。

### 阶段三：SQLAlchemy ORM 实现

**目标：** 按确认后的模型方案完成 ORM 代码。

**工作内容：**

1.  复用 P6-IAM-001 的公共 Base 和 Mixin。
2.  按项目现有规范实现角色、权限及关联模型。
3.  配置主键、外键、关系、索引和约束。
4.  遵循现有 UUID、时间、状态和逻辑删除规范。
5.  完成模型注册。
6.  检查双向关系、关联加载及命名一致性。
7.  不重复定义公共模型。
8.  不修改 P6-IAM-001 已批准的用户和组织模型。

**阶段交付：** ORM 模型代码、模型注册变更及代码检查结果。

**门禁：** ORM 字段、关系和约束必须与阶段二确认的模型方案一致。

### 阶段四：人工 MySQL 建表 SQL 编写

**目标：** 为本任务新增的数据模型编写可审查、可追溯的 MySQL SQL。

**工作内容：**

1.  按项目既有 SQL 目录和命名规范组织文件。
2.  明确表名、字段类型、长度、NULL 和默认值。
3.  定义主键、外键、唯一索引和普通索引。
4.  按批准设计实现 CHECK 等约束。
5.  明确逻辑删除及唯一性约束的实现方式。
6.  使用项目已确定的 MySQL、InnoDB、utf8mb4 和 UUID 存储规范。
7.  明确对象创建顺序及必要的依赖关系。
8.  编写必要的执行说明。

**阶段交付：** 人工维护的 MySQL SQL 文件及执行说明。

**限制：**

-   不使用 `Base.metadata.create_all()` 创建正式数据库结构。
-   不引入 Alembic。
-   不因 SQL 实现便利而改变批准设计。
-   编写 SQL 不等于获得数据库执行授权。

### 阶段五：设计、ORM 与 SQL 一致性检查

**目标：** 确保批准设计、ORM 和人工 SQL 三者一致。

  检查对象                  核对内容
  ------------------------- -------------------------------------------
  业务设计 ↔ 模型方案       实体、关系、业务规则、数据范围
  模型方案 ↔ ORM            字段、类型、关系、状态、约束
  ORM ↔ MySQL SQL           字段类型、长度、默认值、索引、外键、CHECK
  P6-IAM-001 ↔ P6-IAM-002   用户、组织引用关系及公共字段复用
  当前任务 ↔ 后续任务       不提前实现邀请、登录、鉴权和审计业务

**阶段交付：** `02_P6-IAM-002模型与SQL一致性核查报告.md`

**门禁：**
发现差异时先判断是实现偏差还是设计冲突。实现偏差按批准设计修正；设计冲突暂停并提交确认。

### 阶段六：测试准备与验证

**目标：** 为 P6-IAM-002 建立与项目 MySQL 技术基线相符的验证内容。

验证范围按批准设计确定，至少检查适用的：

-   模型导入与注册。
-   字段及关系映射。
-   主键与外键定义。
-   唯一性约束。
-   状态及逻辑删除规则。
-   用户角色关联。
-   角色权限关联。
-   数据权限相关结构（如本任务包含）。
-   SQL 与 ORM 静态一致性。

**阶段交付：** 测试清单、测试代码或验证脚本、执行结果记录。

**门禁：**
未实际执行的测试必须标记为未执行，不得标记为通过。测试需要数据库 DDL/DML
时，必须先取得相应授权。

### 阶段七：数据库实施

**目标：** 在用户指定的数据库环境中实施本任务 SQL，并核对实际结构。

**执行前提：** 用户明确授权目标数据库及本次允许执行的操作。

**工作内容：**

1.  确认目标实例和数据库。
2.  检查同名对象及现有数据影响。
3.  按批准顺序执行本任务 SQL。
4.  记录成功和失败的数据库对象。
5.  只读核查实际表结构、索引、外键和约束。
6.  按授权范围执行数据库行为验证。

**阶段交付：** 数据库实施记录及实际结构核查结果。

**限制：** 未获得明确授权时，只能完成 SQL 编写和静态检查，不得执行 DDL
或 DML；发现同名对象或执行异常时停止，不擅自覆盖或删除。

### 阶段八：任务验收与归档

**目标：** 根据实际交付和验证证据形成 P6-IAM-002 验收结论。

**验收内容：**

1.  批准设计要求是否全部落实。
2.  ORM 模型及模型注册是否完成。
3.  人工 MySQL SQL 是否完成。
4.  设计、ORM、SQL 一致性检查是否通过。
5.  已执行测试与未执行测试是否清楚区分。
6.  数据库实施情况是否有真实证据（如已授权执行）。
7.  是否存在未解决的设计、实现或验证问题。
8.  交付文件是否完整。

**阶段交付：**

-   `03_P6-IAM-002开发记录.md`
-   `04_P6-IAM-002验收报告.md`
-   必要的 SQL、ORM 和检查报告。

**完成判定：** 只有达到项目验收要求并具备相应证据，才能将 P6-IAM-002
标记为正式验收通过。代码完成或 SQL
文件编写完成，不自动等于任务验收完成。
