## 3. 公共模块整体架构

1. `app/main.py` 唯一装配入口：`get_settings()` → 创建 FastAPI → 按 Settings 前缀挂总路由 → 注册全局处理器及追踪中间件。lifespan 的 try/yield/finally 保留，启动调用 setup_logging，无数据库或模型连接。
2. `app/core/config.py`：Pydantic Settings 统一读取；进程环境 > 根 .env > 默认值；lru_cache 单例、frozen，不在业务代码重复构造。8 个 Field 均有中文用途、类型、默认、范围、必填和敏感性说明，类、分组及校验器有中文解释；与 .env.example 一致。HOST 仅校验非空，有效绑定由服务器负责。错误转换隐藏原始输入；当前没有凭据字段，repr=False 不等同未来密钥的完整保护。
3. `app/core/logging.py` 消费 BASE-002 的 LOG_LEVEL/LOG_OUTPUT；自有 Handler 标记复用，重复初始化不增加自有 Handler。统一 JSON 白名单字段；关闭 Uvicorn access 查询串输出，HTTPX 降至 WARNING。外部已有 root Handler 会保留，不能据此承诺任意宿主输出都统一或脱敏。
4. `app/core/middleware.py` 校验单个外部请求 ID，非法、重复、缺失时生成 UUID；ContextVar 与 request.state 同步，响应头覆盖一致。finally 内 token reset，在异常及取消后恢复上下文；并发隔离有测试。响应未开始时兜底转换异常，流式已开始时不能重新发送 JSON，只记录并抛出。
5. `app/core/exceptions.py`：应用异常、参数 422、业务 400、权限 403、系统 500；HTTP 401 映射 AUTHENTICATION_ERROR，保留协议状态与头。未知异常返回固定文案，不公开异常值或绝对路径。参数错误只返回 loc 首层，牺牲字段定位以避免公开用户控制键。HTTP 头及自定义公开消息仍由调用方保证安全。
6. 前端 `index.html` → `main.ts` → Pinia/Router/按需组件 → App 的 router-view。使用命名组件及对应样式，没有安装完整 ElementPlus 插件。路由懒加载；当前演示登录不是实际身份系统。Vite 与 TS 的 @ 均为 src，Vitest mergeConfig 复用 Vite；ESLint 最后使用 Prettier 兼容规则；vue-tsc -b 覆盖 app/node 两个引用项目。
7. `quality.py` 按调用者解释器运行后端检查、切换 frontend 运行 npm，失败返回原退出码；只读质量命令不调用 --fix/--write。Ruff force-exclude 明确排除 docs/logs/scripts/data 等目录，pytest 限定 tests。前端质量范围限定 frontend。

调用方向为 main → middleware/exceptions/logging/config，middleware → exceptions/logging，exceptions → logging，logging → config；router → health。未发现当前公共模块循环依赖、第二套配置入口、重复全局异常注册或重复公共模块。中间件兜底与全局 Exception 处理调用同一函数，在响应发送前的不同层提供保护，不是两套错误契约。

实际健康接口和 `/api` 代理一致：`/api/v1/health` 原路径保留。另有未启用扩展点 `src/api/request.ts` baseURL `/api`，auth.ts 请求 `/auth/login` 等，组合后为 `/api/auth/login`，缺少 `/v1`。现有页面不调用这些接口，所以不影响本次健康联调；M1 接入前须统一，不能写成“所有 API 客户端契约已经一致”。
