## 一、M1 阶段定位与目标

4.  后端认证、功能授权和数据范围控制；
5.  文件存储适配、元数据、上传、下载和鉴权；
6.  公共任务记录、Worker、任务状态查询、受控重试和取消；
7.  通知基础能力；
8.  管理端布局、路由、登录邀请页面、前端权限控制和公共组件；
9.  候选人门户基础布局；
10. 前后端联调、质量回归和 M1 验收。

## 二、M1 前置技术门禁：R09 与 R10

R09、R10 不回归 M0 返工，统一纳入
M1。它们属于相应代码开发前必须完成的设计门禁。

### 2.1 R09：Refresh Token 与 HttpOnly Cookie 契约统一

**问题：** 原认证设计中 Refresh Token 的响应体约定与 HttpOnly Cookie
方案不一致，可能导致前后端刷新流程不一致、浏览器 Cookie
未携带、退出状态不一致或安全策略缺失。

**必须确认：**

1.  Access Token 的返回方式和前端使用方式；
2.  Refresh Token 是否仅通过 HttpOnly Cookie 传输；
3.  Cookie 的 `HttpOnly`、`Secure`、`SameSite`、`Path`、`Domain`
    和有效期；
4.  登录接口如何建立认证状态；
5.  刷新接口如何读取、校验和轮换 Refresh Token；
6.  刷新成功、失败的响应结构；
7.  退出时如何清理 Cookie，是否需要服务端撤销状态；
8.  两类 Token 的有效期和失效策略；
9.  本地开发、代理和跨域情况下 Cookie 的携带规则；
10. CSRF 风险和防护策略；
11. 并发请求同时触发刷新时如何避免重复刷新；
12. 如何防止 Token、Cookie 和认证凭据进入普通日志。

**交付物：**

-   认证与 Token 生命周期决策记录；
-   登录、刷新、退出、当前用户 API 契约；
-   Cookie 属性、跨域和 CSRF 策略；
-   前后端请求/响应示例；
-   认证流程测试用例；
-   API 设计文档修订记录。

**门禁：** R09 必须在 `P6-IAM-004`、`P6-FE-003`
真实认证实现前确认，并作为 `P6-IAM-005` 联调依据。

**约束：** 不得由前后端各自猜测；不得将 Refresh Token 暴露到普通
JavaScript 可读取的存储位置，除非重新评审并批准安全方案；HttpOnly Cookie
不代表 CSRF 风险自动消失；不得记录完整 Token 或
Cookie。具体技术取值必须核对现有 API
设计和工程实现后确定，本文件不假定方案已定。

### 2.2 R10：前端 API 路径与后端 API 前缀统一

**问题：** 前端 API 请求路径与后端实际路由前缀存在不一致风险，可能造成
404、代理转发错误、Mock 与真实接口不一致。

**必须确认：**

1.  当前后端实际 API 路由前缀；
2.  API 详细设计中的版本前缀；
3.  统一 API 根路径，例如核实后再决定是否使用 `/api/v1`；
4.  Axios `baseURL` 与业务 API 相对路径的职责；
5.  Vite 开发代理的匹配与转发规则；
6.  生产反向代理的路径转发约定；
7.  OpenAPI 文档路径与业务 API 路径的区别；
8.  避免业务 API 方法重复拼接版本前缀；
9.  Mock、前端类型、接口测试和真实后端使用同一契约；
10. 路径变更时前后端、代理和测试同步更新的流程。

**交付物：**

-   API 根路径决策记录；
-   前后端 API 路径对照表；
-   Axios 请求封装约定；
-   Vite 代理规则说明；
-   关键接口契约；
-   API 路径测试用例。

**门禁：** R10 必须在 `P6-FE-002` 的 API 请求基础配置和真实 API
联调前确认。

**约束：**
先核对实际后端路由，不得仅凭示例认定前缀；不得通过代理配置掩盖契约不一致；不得只改前端而不检查后端路由、接口文档和测试。

## 四、M1 分阶段实施流程

### 阶段 A：前置设计门禁

1.  检查现有后端认证路由、Token 实现和 API 设计；
2.  检查前端 Axios、路由、代理和 API 模块；
3.  分别形成 R09、R10 问题现状和影响分析；
4.  确认 Token/Cookie 生命周期、CSRF 和并发刷新策略；
5.  确认 API 根路径、Axios baseURL 和代理转发规则；
6.  更新 API 设计、前端工程约定和测试契约；
7.  用户审核关键决策后，进入代码实现。

**出口条件：**
两项门禁均有决策记录；前后端契约一致；不存在需要开发人员自行猜测的关键路径、字段或安全行为。

### 阶段 B：数据库基础能力

**任务：** BASE-006、BASE-007、BASE-008。

**B1 MySQL 连接与会话管理**

-   核对 M0 配置加载机制；
-   建立统一 SQLAlchemy Engine；
-   建立 Session 生命周期管理；
-   为 FastAPI 请求提供受控数据库会话；
-   处理连接失败、事务回滚和资源释放；
-   建立连接、会话、异常和资源释放测试。

验收：连接可用；请求结束后会话释放；事务异常回滚；数据库不可用时错误明确；业务模块不重复创建
Engine。

**B2 数据库初始化与结构变更 SQL 管理**

-   建立人工维护的初始化 SQL（`sql/init.sql`），建表语句依据 SQLAlchemy ORM 模型人工编写；
-   建立结构变更 SQL 目录（`sql/changes/`）与命名规范，按日期与用途命名；
-   明确 SQL 编写、审核、执行与留档流程，变更须经人工审核后执行；
-   验证空数据库按初始化 SQL 建库，结构与 ORM 模型一致；
-   验证变更 SQL 在独立测试库先行执行，再应用于开发库与生产库；
-   形成建库与结构变更执行说明。

验收：初始化 SQL 可重复执行建库；结构变更 SQL 可审查、可追溯；结构与 ORM 模型一致；不以代码自动建表替代审核后的 SQL；不提前创建 M2～M7 全部业务表。

**B3 公共数据库基础模型**

-   明确主键、创建时间、更新时间和状态字段；
-   明确公共模型继承方式；
-   核对索引、唯一约束和外键；
-   按数据库详细设计建立公共模型；
-   建立模型测试和对应的建表 SQL。

验收：公共字段规范统一、模型可复用、建表 SQL 与模型一致。

### 阶段 C：用户、组织、角色与权限模型

**任务：** IAM-001、IAM-002。

**C1 用户与组织模型**

-   实现用户、组织、部门模型；
-   明确关联关系、账号状态和唯一性约束；
-   建立模型、建表 SQL 和查询测试。

验收：关系符合数据库设计；账号状态明确；不开放自主注册。

**C2 角色与权限模型**

-   实现角色和权限资源/权限点；
-   实现用户角色、角色权限关联；
-   实现组织或数据范围授权关系；
-   区分功能权限和数据权限；
-   建立授权查询服务；
-   测试允许、拒绝和边界场景。

验收：有效权限可查询；未授权默认拒绝；后端权限独立于前端菜单；模型符合权限设计文档。

### 阶段 D：邀请制账号、认证和后端授权

**任务：** IAM-003、IAM-004、IAM-005、IAM-006。

**D1 邀请制账号**

-   实现管理员创建账号或发起邀请；
-   生成和校验邀请凭证；
-   校验邀请有效期；
-   在邀请页面显示有效时间提示；
-   实现邀请激活和账号状态变更；
-   处理过期、重复使用和无效邀请；
-   测试成功、过期、重复使用和无权限场景。

验收：只有授权人员可以邀请；邀请有有效期；过期和重复邀请按规则拒绝；不提供自主注册。

**D2 登录、JWT 与当前用户**

-   按 R09 实现登录；
-   实现身份凭证校验；
-   实现 Access Token 生成和验证；
-   按确认方案处理 Refresh Token；
-   实现刷新和轮换；
-   实现退出及认证状态清理；
-   实现当前用户接口；
-   统一认证错误码和响应结构；
-   对敏感凭据日志脱敏；
-   测试登录、错误凭证、过期、刷新、退出和并发刷新。

验收：前后端认证状态一致；刷新符合
R09；失效凭证被拒绝；退出按设计清理状态；不记录完整 Token/Cookie。

**D3 后端认证授权**

-   建立统一当前用户解析；
-   建立认证依赖；
-   建立角色/权限检查依赖；
-   建立数据范围授权服务；
-   接入受保护路由；
-   统一未认证和无权限错误；
-   测试越权和跨组织访问。

验收：未登录、无权限和超出数据范围的请求均被拒绝；前端隐藏菜单不能替代后端授权。

**D4 权限变更与审计**

-   识别需审计的权限变更和重要操作；
-   定义审计事件字段；
-   接入统一审计记录；
-   按已确认的文件/日志存储决定记录；
-   关联用户、时间、操作对象和 request_id；
-   脱敏并测试写入失败、轮转等情况。

验收：重要权限变更可追踪；不记录密码、Token、API
Key；不擅自新增与已确认存储设计冲突的审计表。

### 阶段 E：文件服务

**任务：** FILE-001、FILE-002、FILE-003。

**E1 文件存储适配层**

-   定义统一存储接口；
-   实现首期本地文件系统适配；
-   统一保存、读取、删除和存在性检查；
-   物理路径与业务对象解耦；
-   处理文件名、异常、写入失败和磁盘不足；
-   验证路径安全和路径穿越防护。

验收：业务模块不直接拼接物理路径；不向前端暴露物理路径；异常可诊断。

**E2 文件元数据模型**

-   按数据库设计实现元数据模型；
-   定义文件 ID、原始文件名、存储标识、大小、类型、状态和创建信息；
-   建立索引、约束和建表 SQL；
-   验证元数据与物理文件关联。

验收：MySQL
保存元数据和引用，文件本体存文件系统；不把文件二进制写入元数据表。

**E3 上传、下载和鉴权**

-   实现受控上传；
-   校验文件类型、大小和名称；
-   保存元数据；
-   实现受控下载；
-   下载前执行权限检查；
-   处理元数据缺失、物理文件丢失和存储异常；
-   测试未授权、跨组织和猜测文件 ID 场景。

验收：上传关联正确；未授权不能下载；物理路径不暴露；后续业务可复用文件服务。

### 阶段 F：公共任务与 Worker

**任务：** BASE-009、BASE-010、BASE-011、BASE-012。

**F1 公共任务模型与服务**

-   定义任务 ID、类型、业务关联、发起人；
-   定义状态、创建/开始/结束时间；
-   定义重试次数和执行摘要；
-   定义状态机和非法状态转换；
-   建立查询服务、建表 SQL 和测试。

验收：任务可创建和查询；状态受约束；不把具体业务结果塞进公共任务表；不引入未经确认的
Redis 依赖。

**F2 Worker 执行骨架**

-   建立 Worker 启动入口；
-   定义任务认领和执行接口；
-   实现开始、成功、失败状态更新；
-   记录异常摘要和关联标识；
-   处理进程异常；
-   验证并发认领和重复执行。

验收：任务可认领和执行；状态可追踪；异常可诊断；业务执行逻辑不全部塞进
Worker 入口。

**F3 查询、重试和取消**

-   实现任务列表和详情查询；
-   按权限限制可见范围；
-   定义可重试、可取消状态；
-   限制重试次数；
-   实现取消请求和执行侧协作；
-   测试重复提交、重试、取消竞态。

## 六、共同文件管理与防冲突规则

本节定义共同文件的职责、涉及任务、修改顺序和冲突防护。实际文件路径必须在工程检查时核实，不得按惯例猜路径，也不得扫描用户明确禁止访问的目录。

### 6.1 数据库连接、Session 与公共模型文件

**共同职责：** 统一 Engine、Session 生命周期、事务和公共模型元数据。

**涉及任务：**
BASE-006、BASE-007、BASE-008、IAM-001、IAM-002、FILE-002、BASE-009。

**修改顺序：**

1.  BASE-006 确定唯一 Engine/Session 入口；
2.  BASE-007 建立初始化与变更 SQL 的目录、命名与审核流程；
3.  BASE-008 确定公共 Base；
4.  IAM、FILE、BASE-009 分别增加自己的模型与对应建表 SQL；
5.  统一审查建表 SQL 与模型一致性。

**防冲突：**

-   不允许各模块自行创建 Engine；
-   不允许重复定义 Base；
-   模型通过统一注册入口管理；
-   不允许多人同时修改同一份结构变更 SQL；
-   结构变更冲突先合并设计，再修订 SQL。

### 6.2 数据库初始化与结构变更 SQL 文件

**涉及任务：**

**顺序：** 先初始化 SQL 与基础配置，再公共模型，再 IAM，再文件元数据，再任务模型。

**防冲突：**

-   变更 SQL 执行前须经人工审核，并在独立测试库先行验证；

## 八、M1 端到端验证场景

### 场景一：邀请制账号与认证

``` text
管理员创建账号/发起邀请
 -> 生成邀请凭证
 -> 用户查看有效时间提示
 -> 在有效期内激活
 -> 登录
 -> 获取当前用户
 -> 按 R09 规则刷新认证状态
 -> 退出并清理认证状态
```

验收：不开放自主注册；邀请有效期有效；Token/Cookie 行为符合
R09；登录、刷新和退出状态一致。

### 场景二：用户权限访问

``` text
用户登录
 -> 获取用户、组织和角色信息
 -> 获取有效权限
 -> 前端展示有权限菜单
 -> 请求受保护 API
 -> 后端认证
 -> 后端权限和数据范围校验
 -> 返回数据或拒绝请求
```

验收：前端菜单与权限信息一致；直接请求 API
不能绕过后端授权；数据范围限制有效。

### 场景三：文件上传和下载

``` text
用户登录
 -> 选择文件
 -> 上传
 -> 后端校验
 -> 文件适配层保存本体
 -> MySQL 保存元数据
 -> 下载请求
 -> 后端鉴权
 -> 文件服务读取并返回
```

验收：元数据与文件本体关联正确；未授权下载被拒绝；物理路径不暴露。

### 场景四：公共任务执行

``` text
用户发起任务
 -> 创建任务记录
 -> Worker 认领
 -> 执行
 -> 更新状态
 -> 用户查询
 -> 按状态和权限重试或取消
 -> 保存执行摘要和必要审计信息
```

验收：状态流转正确；失败可诊断；重试和取消受控；无无约束重复执行。

### 场景五：前端基础框架

``` text
打开管理端
 -> 路由判断认证状态
 -> 未登录进入登录页
 -> 登录成功
 -> 获取当前用户和权限
 -> 展示对应菜单
 -> 进入受保护页面
 -> 按 R10 统一 API 路径访问后端
```

验收：路由、菜单、API
请求和后端授权一致；不重复拼接前缀；认证失效处理正确。

## 十一、开发执行与文档管理约定

### 11.1 每项任务开始前

Codex 必须：

1.  检查 Git 分支和工作区状态；
2.  读取用户明确指定的设计和任务文件；
3.  检查任务涉及的实际文件；
4.  列出新增、修改、删除文件；
5.  识别共同文件及其职责；
6.  说明各任务修改内容和先后顺序；
7.  说明如何避免重复修改和相互覆盖；
8.  检查接口、数据和技术决策是否明确；
9.  给出实施步骤和验证命令。

不得因任务需要就扫描用户明确禁止访问的目录。准确文件路径必须实际核实。

### 11.2 实施中约束

-   先确定设计和接口，再写代码；
-   优先增量修改，不随意重写公共文件；
-   共享文件有明确修改顺序和协调责任；
-   不擅自改变业务范围；
-   不擅自新增 Redis；
-   不擅自新增数据库表或改变文件/日志存储决策；
-   不擅自升级或替换依赖；
-   每个配置项有清晰中文说明；
-   不将未验证能力描述为已完成。

### 11.3 每项任务完成后汇报

1.  任务编号和名称；
2.  完成内容；
3.  新增、修改和删除文件；
4.  共享文件修改说明；
5.  数据库结构变更 SQL 变化；
6.  API 契约变化；
7.  测试命令和真实结果；
8.  未解决问题；
9.  当前任务状态；
10. 对后续任务的影响。

任务只有在代码、测试、文档和验收证据齐备后，才能标记为已完成。

### 11.4 任务状态

沿用总体开发流程：

`待开始 -> 进行中 -> 待联调 -> 联调中 -> 待测试 -> 测试中 -> 待验收 -> 已完成`

异常状态：`阻塞`。

阻塞必须记录原因、影响任务和解除条件。不能仅因代码写完就标记已完成。

### 11.5 文档管理

-   正式设计文档：保存经过确认的业务和技术设计；
-   开发日记：记录实际开发、文件变更、测试和问题；
-   技术决策记录：记录 R09、R10 等关键决策；
-   任务验收记录：记录交付物和验收证据；
-   阶段验收报告：汇总 M1 完成情况和遗留风险。

## 十二、风险与待验证事项

  风险/事项                     影响                     处理任务/时机
  ----------------------------- ------------------------ -----------------
  R09 Token/Cookie 契约不一致   登录和刷新无法稳定联调   认证开发前
  R10 API 路径不统一            404 或代理错误           前端 API 接入前
  MySQL 连接池和事务行为        并发和数据一致性         BASE-006
  SQL 与 ORM 模型不一致          建表结构偏差             BASE-007/008
  权限模型边界不清              越权风险                 IAM-002/005
  邀请有效期和重复使用          账号安全风险             IAM-003
  文件路径和访问控制            文件越权、路径穿越       FILE-001/003
  Worker 并发认领和重复执行     重复处理任务             BASE-010
  任务取消与执行竞态            状态与真实执行不一致     BASE-011
  Cookie 跨域与 CSRF            认证失败或安全风险       R09、IAM-004
  前后端权限信息不一致          菜单与实际访问不一致     IAM-005、FE-004
  共享文件并行修改              覆盖和集成冲突           全阶段

处理原则：先验证再决定；设计冲突先更新设计；延期时调整顺序或范围，不取消必要测试、安全和数据保护活动。
