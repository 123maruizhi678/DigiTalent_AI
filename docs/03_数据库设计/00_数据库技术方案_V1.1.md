## 一、技术选型（唯一方案）

| 项目 | 采用方案 | 说明 |
| --- | --- | --- |
| 关系型数据库 | MySQL 8.0.44 | 平台唯一关系型数据库，开发、测试、验收、生产环境一致 |
| ORM 与数据访问 | SQLAlchemy 2.x（当前 2.1.6） | 数据模型定义、会话与事务管理、查询与连接池 |
| MySQL 驱动 | PyMySQL（当前 1.2.3） | 同步驱动，与 SQLAlchemy 搭配使用 |
| 结构初始化 | 人工维护的初始化 SQL 文件（`sql/init.sql`） | 建表语句依据 ORM 模型人工编写，经审核后执行 |
| 结构变更 | 人工编写、审核并执行的变更 SQL（`sql/changes/`） | 按日期与用途命名，纳入版本控制 |
| 数据访问边界 | Repository/DAO + Service | 模块通过自身数据访问层读写，事务以业务服务为边界 |
| 向量数据 | Milvus | 仅承担向量与相似度检索，业务权威数据仍在 MySQL |

决策依据见《02_系统架构设计/可行性评估/02_基础技术组件可行性评估_V1.1.md》第七节。

## 二、数据库对象与命名

- 业务库统一为单个 MySQL 数据库，按模块划分表归属，表前缀体现模块。
- 表名、字段名统一小写英文加下划线；主键统一 `CHAR(32)` UUID，业务唯一标识单独设置。
- 时间字段统一 `DATETIME` 并按 UTC 保存；金额、分值使用合适精度的 `DECIMAL`。
- 状态字段使用 `VARCHAR` 加明确状态集合，不依赖数据库枚举类型。
- 关键业务关系建立外键；唯一性要求通过唯一索引或唯一约束表达。
- 具体表清单、字段长度、默认值、索引与外键名称以《02_数据库详细设计_V1.1.md》为准。

## 三、数据库初始化

1. 初始化 SQL 统一维护在 `sql/init.sql`，内容为经审核的建表、约束、索引与必要的基础字典数据。
2. 初始化 SQL 必须与 SQLAlchemy ORM 模型保持一致；任一侧变更后同步更新另一侧。
3. 初始化脚本只用于新建空库，不承担存量库的结构调整。
4. 执行前必须确认目标数据库身份（环境、库名、账号），并取得授权；执行人与审核人分离。
5. 生产库执行前先备份，执行后核对表、字段、索引、约束与预期一致。

## 四、数据库结构变更

| 环节 | 要求 |
| --- | --- |
| 提出 | 说明变更原因、影响表、影响数据量、兼容性与回退方式 |
| 编写 | 人工编写 SQL，放置于 `sql/changes/`，命名含日期与用途 |
| 审核 | 人工评审字段类型、索引、外键、锁表与数据迁移影响，审核通过方可执行 |
| 验证 | 先在独立测试库执行并验证，再应用于开发库与生产库 |
| 执行 | 由授权人员执行，记录执行时间、数据库、账号与结果 |
| 收尾 | 同步更新 ORM 模型、详细设计文档与变更记录 |

结构变更不设自动升级、自动回滚机制。回退由人工编写回退 SQL 或恢复备份完成，并在变更记录中说明。

## 五、环境隔离

| 环境 | 数据库 | 说明 |
| --- | --- | --- |
| 开发环境 | 开发专用 MySQL 库 | 开发人员联调使用，允许重置 |
| 测试环境 | 独立 MySQL 测试库 | 自动化测试与回归专用，库名、账号、连接配置均独立 |
| 验收环境 | 验收专用 MySQL 库 | 使用经批准的脱敏或合成数据 |
| 生产环境 | 生产 MySQL 库 | 不承接测试，不接受未审核的结构变更 |

- 各环境配置通过统一配置管理（Pydantic Settings）读取，敏感信息只从环境变量或 `.env` 注入。
- 连接串、库名、账号不得在代码中硬编码；生产库凭据不得出现在仓库、测试配置与日志中。

## 六、测试数据库要求

- 数据库相关测试统一在独立 MySQL 测试库执行，测试库与开发库、生产库严格隔离。
- 测试库表结构由人工维护并审核的初始化 SQL 创建，不使用自动建表。
- 测试用例不得连接生产数据库，也不得通过配置回退到开发库或生产库。
- 涉及生成列、排序规则、触发器、并发与 DDL 行为的验证，只在 MySQL 环境完成并留证。
- 测试数据使用合成数据或经批准的脱敏数据，测试结束后按需重置测试库。

## 七、安全与审计

- 应用连接使用最小权限账号：业务账号仅有业务表 DML 权限，DDL 由具备授权的运维账号在审核后执行。
- 敏感字段（证件号、手机号、密码哈希）分级保护，密码使用安全哈希算法存储。
- 关键数据变更写入操作审计表，记录操作者、时间、对象与变更内容。
- 备份策略、恢复验证与保留期限见《01_数据库总体设计_V1.1.md》第十二节。
