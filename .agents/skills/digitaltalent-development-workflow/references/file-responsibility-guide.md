# 文件职责分析与共享文件修改指南

用途：指导开发任务在修改文件前识别职责、调用关系和潜在覆盖风险。按任务影响范围选择分析深度，不要求每个任务执行全部步骤。

## 1. 适用范围与分析等级

适用于：
- 被多个任务反复修改的公共文件；
- 公共基础层、配置、路由聚合、模型注册、应用入口、依赖清单和测试夹具；
- 本次任务会影响多个模块或调用方的文件。

| 等级 | 适用情况 | 必要分析 |
|---|---|---|
| 轻量 | 单个局部文件、低影响修改 | 文件当前职责、直接调用方、关联测试 |
| 标准 | 多文件或模块间调用 | 文件清单、职责边界、调用/注册关系、修改顺序 |
| 完整 | 公共基础设施、跨模块或架构变更 | 标准分析 + 历史改动、下游影响、扩展模式、回归范围 |

## 2. 文件当前职责

判定依据优先级：

1. 文件头部注释或模块 docstring；
2. 目录约定；
3. 实际导入和调用关系；
4. 关联测试。

一个文件应有明确的主要职责。发现职责混杂时，先记录问题，不以“顺手整理”为由擅自重构。

简要记录格式：

```text
文件：app/core/config.py
当前职责：统一配置定义与校验
职责边界：不建立连接、不执行业务逻辑
本次修改：仅增加本任务需要的配置项
明确不改：已有无关字段、校验器和默认值
```

## 3. 历史修改与共享文件

标准/完整任务涉及共享文件时，核对历史改动：

- 文件内任务注释；
- `git log --oneline -- <file>`；
- 必要时使用 `git log -p --follow -- <file>`；
- 关联测试和当前实际行为。

历史记录用于理解意图，不替代当前状态核验。

## 4. 修改计划

对每个需要修改的共享文件，说明：

- 文件路径和当前职责；
- 修改位置；
- 新增、修改或删除的内容；
- 明确不改动的部分；
- 关联验收标准；
- 对调用方和后续任务的影响。

涉及删除、重命名或职责调整时，必须单独说明影响面和替代方案。不得出现“顺便优化”“顺便格式化”等无关修改。

## 5. 调用关系与修改顺序

标准/完整任务应画出本次涉及的最小调用图，包含必要的：
- import / 调用关系；
- 注册或装配关系；
- 测试覆盖关系。

修改顺序遵循依赖方向：基础设施层 → 数据层/模型层 → 服务层 → 接口层 → 应用装配 → 测试。

若任务实际依赖顺序不同，应说明原因。多个任务会修改同一共享文件时，应串行执行，避免并行覆盖。

## 6. 避免重复实现

- 先搜索当前相关范围，再新增能力；
- 配置、连接、路由、模型和公共逻辑遵循项目现有单一来源；
- 复用已有实现，不复制第二套逻辑；
- 发现同一能力已有多个实现时，先报告冲突，不再新增第三套。

## 7. 避免相互覆盖

修改前检查：

```powershell
git status --short
git diff -- <文件路径>
```

规则：

1. 文件存在用户未提交修改时，不整文件覆盖。
2. 优先精确增量修改，保留无关内容、注释和顺序。
3. 需要大面积重写时，先向用户说明并等待确认。
4. 不因格式化工具而重排无关内容。
5. 不擅自清理无关变更。

## 8. 修改后的验证

共享文件修改后，根据影响范围选择验证：

1. 静态检查：相关文件 Ruff 检查；必要时执行项目范围检查。
2. 关联测试：直接测试及受影响下游模块测试。
3. 行为验证：仅在任务涉及真实启动、连接或外部服务时执行，并确保有授权和安全隔离。

验证记录：

| 文件 | 修改内容 | 静态检查 | 关联测试 | 行为验证 | 结论 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

通过标准：原有相关功能未被破坏；新增行为有对应测试；未出现与任务无关的改动。

## 9. 常见共享文件提示

| 文件 | 职责 | 常见风险 |
|---|---|---|
| `app/core/config.py` | 配置定义与校验 | 重复字段、配置示例不一致 |
| `app/core/database.py` | 数据库连接与会话 | 引擎重复创建、会话作用域改变 |
| `app/core/orm.py` / `app/core/model_mixins.py` | ORM 基类与混入 | 修改基类影响全部模型 |
| `app/api/router.py` | 路由聚合 | 重复注册、prefix 冲突 |
| `app/models/__init__.py` | 模型集中导出 | 模型未注册导致元数据不完整 |
| `app/main.py` | 应用装配 | 中间件或路由顺序改变 |
| `requirements/base.txt`、`dev.txt` | 依赖声明 | 版本漂移、重复声明 |
| `tests/conftest.py` | 测试夹具 | fixture 名称或作用域改变 |
